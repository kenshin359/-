# Libetee 売上経営プラットフォーム（参謀室）

「売上・転換率報告」を土台に、**売上管理・売上予想・広告費管理・楽天/Amazonイベント管理**まで
一気通貫で回す、社長 × 参謀（Claude）の作戦本部です。目的は **月商1億 → 10億**。

- **組織の設計図** … [`docs/参謀室_組織設計書.md`](docs/参謀室_組織設計書.md)（まずここを読む）
- **2つの実働チーム** … `.claude/agents/`（予想チーム／分析チーム。実際に動くサブエージェント）
- 本リポジトリ … kintone 売上日報を**自動構築**し、**過去データを移行**し、**予想・分析**するスクリプト

## できること

| コマンド | 内容 |
|---|---|
| `npm run apps` | アプリ一覧とIDを表示（移行元IDの確認用） |
| `npm run create-app` | 「売上日報（新）」アプリを自動作成（フィールド＋デプロイまで） |
| `npm run migrate` | 既存の文章データをパースして新アプリへ投入 |
| `npm run analyze` | 売上・広告費・ROAS・チャネル別・イベント日vs平常日を集計し、数値を書き出し |
| `npm run forecast` | **次のイベント日にいくら売れるか**を予想（弱気/本命/強気の3本立て） |
| `npm run calendar` | 楽天/Amazon のイベント暦（次に来るイベントを表示） |

## 2つのチームの呼び方

参謀に一言頼めば、実働チームが動きます。

- 「**予想チーム**、次のスーパーSALE いくらいく？広告いくら張る？」
- 「**分析チーム**、先月なんで楽天が落ちた？次どう埋める？」

## データ構造（1日1レコード）

日付ごとに「チャネル別実績」テーブル（**楽天/Amazon/自社サイト/TikTok/Qoo10/BASE**）を持ち、
各チャネルの **売上・広告費・売上個数・アクセス数・転換率・いいね率・まとめ買い率** を毎日落とし込みます。
その日の **イベント区分・イベント名**（例：お買い物マラソン／プライムデー）も記録し、予想・分析の土台にします。

## セットアップ

```bash
cp .env.example .env   # 値を記入（.env はコミットされません）
```

`.env` に設定する項目は `.env.example` を参照。認証は2種類：

- **パスワード認証**（`KINTONE_USER` + `KINTONE_PASSWORD`）… アプリ**作成**に必須。
  専用の連携用アカウントを推奨（社長個人アカウントは避ける）。
- **APIトークン認証**（`KINTONE_API_TOKEN`）… レコードの読み書き。アプリごとに発行、read/write 権限を付与。

## 進め方（推奨順）

```bash
npm run apps                 # ① 既存アプリのIDを確認 → .env の KINTONE_OLD_APP_ID に設定
npm run create-app           # ② 新アプリを作成 → 表示された ID を KINTONE_NEW_APP_ID に設定
DRY_RUN=1 npm run migrate     # ③ まず抽出結果だけ確認（out/preview.json）
npm run migrate              # ④ 問題なければ本投入
npm run analyze              # ⑤ 集計・分析
```

## 安全について

- 認証情報は**すべて環境変数**から読み込み、コードには一切書きません。
- `.env` と秘密情報は `.gitignore` で除外済み。リポジトリには入りません。
- セットアップ後は API トークンやパスワードを**いつでも失効・変更**できます。
