# AI経営チーム — 構成と運用ルール

これまでは「日報を要約する1つのAI」でした。
それを、**大手コンサルのチーム編成に倣って部署に分けた**ものがこの構成です。

理由は3つあります。

1. **1つのAIに全部を見せると、視点が平均化して指摘が薄くなる**
   「在庫の目」と「安全の目」は本来まったく別の見方です。
2. **部署ごとに、見るデータを絞れる**
   広告の分析に日報の全文は要りません。渡す情報が減るぶん、精度が上がり費用も下がります。
3. **どの部署が何を言ったか分かる**
   おかしな指摘が出たとき、原因の切り分けができます。

```
        ┌───────────┬───────────┼───────────┬───────────┐
        │           │           │           │           │

   │01 経営企画│ │02 財務  │ │03 マーケ│ │04 SCM  │ │05 品質 │ │06 人事 │
   │  Strategy │ │ Finance │ │  CMO室  │ │ 在庫   │ │ リスク │ │ 現場   │
   └──────────┘ └────────┘ └────────┘ └────────┘ └────────┘ └────────┘
```

| # | 部署 | 何を見るか | 入力データ |
|---|------|-----------|-----------|
| 01 | 経営企画室 | 打ち手と優先順位 | 他部署の要約のみ |
| 02 | 財務 | 売上・広告費・粗利感・異常値 | 集計済みの数字 |
| 03 | マーケティング | 転換率・アクセス・ROAS・商品別 | 集計済みの数字 |
| 04 | サプライチェーン | 欠品・在庫・機会損失 | 在庫数と販売個数 |
| 05 | 品質・リスク | 安全・法令・クレーム | 日報の要約 |
| 06 | 人事・現場 | 提出率・稼働・負荷 | 日報のメタ情報 |
| 00 | 統括 | 全体を1枚にまとめる | 各部署の出力 |

## 全部署に共通する鉄則

### ① 計算はAIにさせない

金額・件数・比率は **すべてJavaScript側で計算してから** 渡します。
AIに何千行もの足し算をさせると数字がずれます。
**AIの仕事は計算ではなく解釈です。**

### ② 渡されたデータにしか触れない

推測で数字を作らない。書かれていないことは「情報不足」と書く。

### ③ 指摘が無ければ「特記事項なし」

無理に何かをひねり出させない。毎日それらしい文章が並ぶと、
本当に重要な日を見落とします。

### ④ 出力はJSONのみ

前後に説明文やマークダウンのフェンスを付けない。

### ⑤ データが無い部署は動かさない

在庫アプリが無ければ 04 は動かしません（費用の無駄・幻の指摘の防止）。

## 費用について

部署を増やしても費用はほとんど変わりません。
渡すのが「集計済みの短い数字」だけだからです。

| 構成 | 1回あたり | 月20回 |
|---|---|---|
| 旧: 1つのAIに全部 | 約3円 | 約60円 |
| 新: 6部署＋統括 | 約8円 | 約160円 |

日報画像の読み取り（1枚あたり数円）の方が費用は大きく、
部署を分けたこと自体の増加は誤差の範囲です。
