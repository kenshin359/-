# 楽天レビュー返信の下書き自動生成 — 手順

CS担当が**コピペするだけ**で返信できるよう、レビューごとの下書きを自動で作ります。

---

## 先に、できること・できないことを整理します

| | |
|---|---|
| ❌ **完全自動で投稿** | できません。楽天にレビュー返信のAPIがありません（RMSの管理画面から手動） |
| ✅ **下書きの自動生成** | できます。レビュー1件ごとに、内容に合わせた返信文を作ります |
| ✅ **Chatworkへ自動配信** | できます。CS担当は貼り付けるだけです |
| ✅ **要注意レビューの検知** | できます。星3以下・安全・不良・返金の話題は必ず印を付けます |

**APIが無いから手動、という理由だけではありません。**
お客様に向けた文面を、人が一度も見ないまま出すべきではないと考えています。

---

## 届くもの

```
──────────────
★5　2026/07/29　ポンコナンさん　✅ そのまま使えます
話題: 梱包・手紙

【お客様のレビュー】
お手紙がついていたり、カードホルダーが綺麗な封筒に入っていたり。梱包も綺麗。

【返信の下書き（ここからコピー）】
弊社楽天ショップをご利用いただき誠にありがとうございます。
お客様からの貴重なご感想をいただけて、とても嬉しく思います。
お手紙やカードホルダーの封入、梱包につきましてお褒めのお言葉をいただき、
大変光栄です。…
（以下、いつもの結び）
```

星3以下や、安全・不良・返金に触れるレビューには **⚠️ 要確認** が付き、
その理由も表示されます。**⚠️ が付いたものは、必ず読んでから投稿してください。**

---

## 仕組み（なぜ文体がぶれないのか）

いま投稿されている返信323件を分析したところ、はっきりした型がありました。

| 部分 | 出現率 | 誰が書くか |
|---|---|---|
| ①「弊社楽天ショップをご利用いただき…」 | 82% | **固定文** |
| ②「貴重なご感想をいただけて…」 | — | **固定文** |
| ③ そのお客様だけに向けた本文 | — | **★AIが書く** |
| ④ 謝罪・改善（不満があるときだけ） | 25% | **★AIが書く** |
| ⑤「お気軽にお問い合わせください」 | 55% | **固定文** |
| ⑥「数ある楽天ショップの中から…」 | 94% | **固定文** |

**AIが書くのは ③④ だけです。** 前後は `config/reply-blocks.json` の固定文なので、

- 文体がぶれない
- AIが余計なことを言う余地が構造的に無い
- 渡す文章が短く、費用がほとんどかからない
- 文面を変えたいときは設定ファイルを直すだけ

---

## 事実カード — 嘘を書かせないための仕組み

`config/reply-blocks.json` の `facts` に書かれていることしか、AIは事実として書けません。

```json
"facts": {
  "永久保証": "部品代は無償で対応。ただし送料のみお客様のご負担をお願いしている。",
  "同梱物": "スーツケースカバーとネームタグをお付けしている。",
  "キャスター": "HINOMOTO製キャスターを採用。"
}
```

さらに、**出来上がった文面も機械的に点検**します。

| 点検内容 | 例 |
|---|---|
| 送料を無料・弊社負担と書いていないか | 「送料無料で対応いたします」→ 指摘 |
| 返金・交換を確約していないか | 「新品と交換いたします」→ 指摘 |
| 「必ず」「絶対に」を使っていないか | 指摘 |
| 具体的な納期を約束していないか | 「3営業日以内にお届け」→ 指摘 |

**「送料のみお客様のご負担をお願いしております」という正しい説明は、指摘されません。**
（正しい文と間違った文を区別できることを、テストで確認しています）

## 設定

`.env` に3行足すだけです。

```
RAKUTEN_SHOP_ID=407466
RAKUTEN_ITEM_IDS=10000012
ANTHROPIC_API_KEY=sk-ant-...
```

`RAKUTEN_SHOP_ID` は、レビューページのURLに出てくる数字です。

```
https://review.rakuten.co.jp/shop/4/407466_407466/
                                    ↑ これ
```

`RAKUTEN_ITEM_IDS` は商品レビューも見る場合のみ（カンマ区切りで複数可）。

## 使い方

### 初回だけ

```bash
npm run replies -- --init
```

いま出ているレビューを「処理済み」にします。
**これをやらないと、過去のレビュー全部の下書きが一度に届きます。**

### 毎回

```bash
npm run replies
```

未返信のレビューを拾って下書きを作り、Chatworkに送ります。

| オプション | 意味 |
|---|---|
| `--dry-run` | 送らずに画面に表示（まずこれで確認） |
| `--limit=20` | 一度に作る件数の上限（既定10件） |
| `--pages=3` | 取得するページ数（1ページ30件） |

---

## 費用

1件あたり **1円未満**です。渡すのはレビュー本文と事実カードだけで、
AIが書くのも150字程度だからです。

1日10件の下書きを毎日作っても、**月100円ほど**です。

---

## 自動化（毎朝まとめて届くようにする）

n8n に登録すれば、毎朝決まった時刻に前日分の下書きが届きます。
まずは手動で数日回して、文面が実務に耐えるか確認してから自動化することをおすすめします。

---

## ⚠️ いま把握しておくべきこと

レビューを分析したところ、**ショップレビューへの返信率は 0.3%**（720件中2件）でした。
一方、商品レビューには 48.9% 返信しています。

そして、CSチームが褒められているのは**ショップレビューの方**です。
ここに返信できるようになるのが、この仕組みの一番の狙いです。
