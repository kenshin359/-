# Shopify（自社サイト）の売上を自動でキントーンへ

CSVのダウンロードは要りません。**Shopifyから直接**取ってきます。

---

## 1. キントーン側の土台は、すでにあります

新しくアプリを作る必要はありません。**そのまま使えます。**

| 必要なもの | 状態 |
|---|---|
| 売上を入れるアプリ | ✅ **売上明細（自動取込）** アプリ（既存） |
| 「自社サイト」という販売先 | ✅ 最初から選択肢にあります |
| 1日1レコードの形 | ✅ Amazon・楽天と同じ形。並べて見られます |
| 二重登録を防ぐしくみ | ✅ 対象日で自動判定（何度動かしても増えません） |
| 商品の紐づけ | ✅ `config/sku-map.json` を Amazon と共用 |
| グラフ（販売先別・商品別） | ✅ 自社サイトも自動で混ざります |

**足りないのは Shopify から取ってくる部分だけ**でした。それを今回作りました。

> ⚠️ 1点だけ確認が要ります。
> Shopify側のSKUが、Amazonと**同じ番号**（`101` `a207` `F53K02` など）かどうか。
> 違う番号なら、Shopify用のSKUを `config/sku-map.json` に足す必要があります。
> 最初の1回を `--dry-run` で流せば、足りないSKUが一覧で出ます。

---

## 2. Shopify側の準備（10分・1回だけ）

1. Shopify管理画面 →「**設定**」→「**アプリと販売チャネル**」
2. 右上「**アプリを開発**」→「**アプリを作成**」
3. 名前は `キントーン連携` などでOK
4. 「**Admin API 統合を設定**」を開き、次の**2つだけ**にチェック

   | 権限 | なぜ必要か |
   |---|---|
   | `read_orders` | 注文（売上）を読むため |
   | `read_products` | 商品名・SKUを読むため |

   > ⚠️ 書き込み権限（`write_`）は**1つも付けないでください。**
   > 万一トークンが漏れても、ストアを書き換えられません。

5. 「**保存**」→「**アプリをインストール**」
6. 「**Admin APIアクセストークン**」を**表示して1回だけコピー**

   > ⚠️ この画面を閉じると**二度と表示されません**。
   > ⚠️ このトークンは**チャットに貼らないでください。**GitHubのSecrets画面に直接入力してください。

7. 過去60日より前の注文も読む場合は、`read_all_orders` の申請が別途必要です
   （毎日動かすぶんには不要です）

## 3. どちらの動かし方を選ぶか

**同じことができます。おすすめは A です。**

| | **A. GitHub Actions（おすすめ）** | **B. n8n** |
|---|---|---|
| 追加で契約するもの | なし（今使っているGitHubのまま） | n8nの契約が必要 |
| SKU対応表 | **1か所**（`config/sku-map.json`） | **2か所**（n8nの中にも書き写す） |
| 動作確認 | テスト364件で自動チェック | 手で確認 |
| 画面で流れが見える | ✕（ログのみ） | ◯（図で見える） |
| 設定の手間 | Secretsを2つ足すだけ | 読み込み＋設定値の入力 |

**Bの一番の弱点**は、SKU対応表が2か所になることです。
片方だけ直すと、n8nが古い商品名で登録し続け、**誰も気づきません。**
そのため、2つがズレたらテストが落ちるようにしてあります（`test/shopifyN8n.test.js`）。

## 4. A. GitHub Actions で動かす（おすすめ）

### 4-1. Secrets を2つ足す

リポジトリ →「Settings」→「Secrets and variables」→「Actions」→「New repository secret」

| 名前 | 値 |
|---|---|
| `SHOPIFY_SHOP_DOMAIN` | `libetee.myshopify.com`（`https://` は付けない） |
| `SHOPIFY_ADMIN_TOKEN` | `shpat_` で始まるトークン |

`KINTONE_BASE_URL` / `KINTONE_USER` / `KINTONE_PASSWORD` /
`KINTONE_SALES_DETAIL_APP_ID` は既存のものを使います。

### 4-2. 動かしてみる

「**Actions**」タブ →「**Shopify売上取込（毎朝8:00）**」→「**Run workflow**」

- そのまま実行すると**昨日ぶん**を取り込みます
- `from` / `to` に日付を入れると、その期間をまとめて取り込めます
  （例: `2026-07-01` 〜 `2026-07-31` で7月を一気に）

うまくいけば、あとは**毎朝8:00に自動**で動きます。

### 4-3. 手元で試す場合

```bash
npm run shopify:import -- --dry-run              # 書き込まず内容だけ
npm run shopify:import                            # 昨日ぶん
npm run shopify:import -- --date=2026-07-31
npm run shopify:import -- --from=2026-07-01 --to=2026-07-31
```

## 5. B. n8n で動かす

### 5-1. 読み込む

n8n →「Workflows」→「Import from File」→
`n8n/workflow-7-shopify-sales.json` を選ぶ

### 5-2. 設定値を入れる

n8n の「**Variables**」に次を登録します（Settings → Variables）。

| 名前 | 値 |
|---|---|
| `SHOPIFY_SHOP_DOMAIN` | `libetee.myshopify.com` |
| `SHOPIFY_ADMIN_TOKEN` | `shpat_…` |
| `SHOPIFY_API_VERSION` | `2026-01`（空でも可） |
| `KINTONE_SUBDOMAIN` | `w6pq7i12hn4b` |
| `KINTONE_SALES_DETAIL_APP_ID` | `29` |
| `KINTONE_API_TOKEN_SALES_DETAIL` | 売上明細アプリのAPIトークン |
| `CHATWORK_API_TOKEN` | Chatworkのトークン |
| `CHATWORK_SALES_ROOM_ID` | 通知先のルームID |

> Aと違い、n8nは**APIトークン**で動きます。
> キントーンで 売上明細アプリ → 設定 → APIトークン →
> 「**レコード閲覧・追加・編集**」にチェックして生成してください。
> パスワードを渡さずに済むぶん、こちらの方が安全です。

### 5-3. 中身の流れ

```
毎朝8:00
  → 対象日を決める（昨日・日本時間）
  → Shopifyから注文を取る
  → 商品ごとにまとめる（SKU対応表で紐づけ）
  → その日のレコードを探す
  → キントーン用に組み立てる（自社サイト以外の明細は残す）
  → 上書き / 新規登録
  → Chatworkに報告
```

### 5-4. 商品が増えたときは

`config/sku-map.json` に足したあと、**n8nの「商品ごとにまとめる」ノードの
`SKU_MAP` にも同じ行を足してください。** 2か所です。

忘れると `npm test` が落ちて教えてくれます。

## 6. 数字の決まりごと（Amazonと揃えています）

| 項目 | 扱い |
|---|---|
| 売上 | 商品の金額（割引を引いたあと）。**送料は含めません** |
| 税 | ストアが**税別設定**のときだけ税を足します（税込設定なら足しません） |
| キャンセル注文 | **数えません**（何件除外したか表示します） |
| テスト注文 | **数えません** |
| 日付 | **日本時間**で判定（Shopifyの記録はUTCなので、そのままだと朝9時前の注文が前日にずれます） |
| 対応表に無いSKU | 「未分類・**要確認**」。**推測で商品名を付けません** |

### 返品について

**返品（Refund）は差し引いていません。** Amazon側も同じ扱いです。
「注文された金額」で揃えたほうが、販売先どうしを比べられるためです。
返品込みの純売上が必要になったら、別途お知らせください。

---

## 7. 何度動かしても二重になりません

同じ日を何度取り込んでも、**その日の「自社サイト」の明細だけ**が入れ替わります。
Amazon・楽天の明細は必ず残ります。

そのため、**あとから日付を指定してやり直しても安全**です。

---

## 8. まだ確認できていないこと

**実際のShopifyストアにはまだ一度も接続していません。**
トークンをいただいていないためです。

- 動作の筋道はテスト（`test/shopify.test.js` 9件）で確認済みです
- ただし**実物の注文データで動かしたのは0回**です
- 最初の1回は必ず `--dry-run`、または Actions の手動実行で、
  **金額がShopifyの管理画面と一致するか**を見比べてください

一致しなければ、そのまま出た数字をお知らせください。その場で直します。
