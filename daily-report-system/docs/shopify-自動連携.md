# Shopify（自社サイト）の売上をキントーンへ

---

## 1. キントーン側の土台は、すでにあります

新しくアプリを作る必要はありません。

| 必要なもの | 状態 |
|---|---|
| 売上を入れるアプリ | ✅ **売上明細（自動取込）**（Amazon・楽天と同じアプリ） |
| 「自社サイト」という販売先 | ✅ 最初から選択肢にあります |
| 1日1レコードの形 | ✅ 並べて比較できます |
| 二重登録を防ぐしくみ | ✅ 何度入れても増えません |
| 商品の紐づけ | ✅ `config/sku-map.json` をAmazonと共用 |
| グラフ | ✅ 自社サイトが自動で混ざります |

---

## 2. どの方式で取り込むか

Shopifyには2つの道があります。どちらでも同じ結果になります。

| | **A. APIで自動取得**（おすすめ） | B. CSVを提出ボックスに置く |
|---|---|---|
| 毎朝の作業 | **なし**（毎朝8:00に自動） | エクスポート → 提出ボックスに置く |
| 準備 | トークン発行 約10分（1回だけ） | なし |
| 商品別の集計 | ✅ できる | ✅ できる |
| Amazon・楽天と比較 | ✅ できる | ✅ できる |
| 返品・キャンセルの反映 | ✅ 毎回その日を読み直すので正しくなる | エクスポートし直せば同じ |

**AとBは同じアプリ・同じ形式に入ります。**どちらで始めても、後から乗り換えられます。

### A のトークンについて

Admin APIのアクセストークン（`shpat_`）は、以前は
「設定 → アプリと販売チャネル → アプリを開発」に表示されていましたが、
**Shopifyはこの方式を廃止しました**（2026年8月時点、このストアでは
「アプリを作成」ボタン自体がありません）。

そのため、Shopifyが定めた正規の手順（OAuth）で1回だけ発行します。
手順は **`docs/shopify-トークン発行.md`** にまとめてあります（約10分）。

---

## 3. A方式（自動）の使い方

トークンを登録したら、あとは自動です。手で動かしたいときは:

```bash
npm run shopify:import                                  # 昨日ぶん
npm run shopify:import -- --date=2026-07-31
npm run shopify:import -- --from=2026-07-01 --to=2026-07-31
npm run shopify:import -- --dry-run                     # 書き込まず内容だけ
```

GitHub Actions の「**Shopify売上取込（毎朝8:00）**」からも手動実行できます。

---

## 4. B方式（CSV）のやり方

### CSVを出す

1. Shopify管理画面 →「**注文管理**」
2. 期間を絞る（前日ぶんなど）
3. 右上の「**エクスポート**」→「**現在の検索結果に一致する注文**」
4. 形式は「**CSV（Excel、Numbers、その他の表計算ソフト用）**」
5. ダウンロード

### キントーンに置く

「日次CSV提出ボックス」のその日のレコードを開き、
**「売上｜Shopify(自社)」**の欄にファイルを添付するだけです。

Amazon・楽天とまったく同じ操作です。**新しく覚えることはありません。**

### 取り込む

```bash
npm run sales:import                     # 提出ボックスの今日ぶん
npm run sales:import -- --date=2026-07-31
npm run sales:import -- --dry-run        # 書き込まず内容だけ
```

手元のファイルを直接読ませることもできます。

```bash
npm run sales:import -- --file=orders_export.csv --channel=自社サイト
```

## 5. CSVのくせ（対応済み）

Shopifyの注文CSVは、間違えても**エラーにならず、静かに売上が減る**形をしています。
次の2つを取り違えると誰も気づけないため、テストで固定しています。

### ① 1注文が複数行に分かれ、2行目以降は注文日が空

```
Name,  Created at,           Lineitem name,      Lineitem price, Lineitem quantity
#1001, 2026-07-30 10:12 ..., 多機能スーツケースS, 26800,          1
#1001, （空）,               ハンディファン,       1600,           2      ← 日付が無い
```

普通に読むと2行目が「日付なし」として捨てられます。
**同じ注文番号の日付を引き継ぐ**ようにしています。

### ② 金額は「1個あたりの単価」

`Lineitem price` は単価です。**数量を掛けないと、まとめ買いが1個ぶん**になります。

---

## 6. 数字の決まりごと（Amazon・楽天と揃えています）

| 項目 | 扱い |
|---|---|
| 売上 | 単価 × 数量 − その商品の割引。**送料は含めません** |
| 税 | 日本のストアは税込価格が標準なので、単価に税が入っている前提 |
| キャンセル注文 | **数えません**（何件除いたか表示） |
| テスト注文 | **数えません**（Bogus Gateway で判定） |
| 返品 | **差し引きません**（Amazonと同じ扱い。金額は別途表示） |
| 注文数 | 行数ではなく**注文の数**で数えます |
| 対応表に無いSKU | 「未分類・**要確認**」。**推測で商品名を付けません** |

### 税設定の取り違えを自動で検知します

明細の合計と、Shopifyが出した**注文の小計（Subtotal）**を毎回突き合わせています。
0.5%以上ずれていたら、

> ⚠ 注文の小計との差 ○○円（○%）。ストアの税設定（税込／税別）が想定と違う可能性があります。

と表示します。**黙って数字を合わせにいきません。**

## 7. 最初にやること

Shopify側のSKUが、Amazonと**同じ番号**（`101` `a207` `F53K02` など）かどうかを確認します。

```bash
npm run sales:import -- --file=orders_export.csv --channel=自社サイト --dry-run
```

- 「✅ すべてのSKUが対応表にあります」と出れば、そのまま使えます
- 「まだ対応表に無いSKU」が出たら、その行を `config/sku-map.json` の `entries` に足してください

商品名を新しく足した場合は、キントーンの選択肢も1回だけ更新します。

```bash
npm run kintone:sync-options
```

---

## 8. 何度取り込んでも二重になりません

同じ日を何度入れても、**その日の「自社サイト」の明細だけ**が入れ替わります。
Amazon・楽天の明細は必ず残ります。あとからやり直しても安全です。
