# Kintone「売上明細（自動取込）」アプリ

Amazonなどの売上レポートを読んで、**商品ごとに自動で紐づける**アプリです。

---

## 1. 作り方

```bash
npm run create-business-apps salesdetail
```

表示された `KINTONE_SALES_DETAIL_APP_ID=29` を `.env` に貼り付けてください。

---

## 2. なぜ既存の売上アプリに書き足さないのか

「売上・転換率報告」アプリは**スタッフが手で入力している**アプリです。
そこに自動で書き足すと、**どちらが正しいのか分からなくなります。**

そのため別アプリにして、**突き合わせて差が出たときに気づける**形にしています。
慣れてきたら、手入力のほうを減らしていけます。

---

## 3. 商品の紐づけ方（ここが肝です）

Amazonのレポートには、社内で使っている商品名は入っていません。
入っているのは **SKU**（自分で付けた管理番号）と **ASIN**、そして Amazon上の商品名です。

そこで3段階で紐づけます。**確実な順**です。

| 順番 | 判定 | 結果 |
|---|---|---|
| ① | SKU が `config/sku-map.json` にある | **確定** |
| ② | ASIN が対応表にある | **確定** |
| ③ | 商品名から推測できる | **要確認**（断定しない） |
| ④ | どれにも当たらない | 未分類・**要確認** |

**③で推測はしますが、絶対に「確定」とは言いません。**
売上を違う商品に付けると、伸びている商品を見誤るためです。

### 対応表の育て方

```bash
npm run sales:import -- --dry-run
```

を実行すると、**まだ登録されていないSKUが金額の大きい順**で出ます。

```
════════ まだ対応表に無いSKU ════════
       ¥29,800 1個  Libetee スーツケース Mサイズ マットブラック 多機能
      { "sku": "LBT-SC-M-MTBK", "asin": "B0CXXXX222", "product": "多機能PC" },
       ¥11,940 3個  Libetee ハンディファン スケルトン ホワイト
      { "sku": "LBT-FAN-SKEL-WH", "asin": "B0CXXXX333", "product": "ハンディファン(スケルトン)" },
```

この行を `config/sku-map.json` の `entries` に貼るだけです。
**`product` の値が正しいかは必ず確認してください**（商品名からの推測が入っています）。

一度登録すれば、**次回から永久に「確定」**になります。

### 新しい商品を足したときは（1回だけ）

アプリの「商品」は**選択式（ドロップダウン）**です。
`config/product-aliases.json` に新しい商品を足したら、次を1回実行してください。

```bash
npm run kintone:sync-products -- --dry-run   # 何が増えるか確認
npm run kintone:sync-products                # 反映
```

これをやらないと、**選択肢に無い商品名は書き込めず、その日の取込が止まります。**
選択肢は増やすだけで、既にあるものは消しません（過去のレコードが壊れるため）。

## 4. 使い方

```bash
npm run sales:import                                  # 提出ボックスの今日ぶん
npm run sales:import -- --date=2026-07-31
npm run sales:import -- --dry-run                     # 書き込まず内容だけ
npm run sales:import -- --file=amazon.csv --channel=Amazon
```

- 同じ日・同じ販売先を2回取り込んでも**二重になりません**（その販売先だけ入れ替え）
- 楽天・Shopify・TikTok のファイルも、同じ仕組みで読みます

---

## 5. 対応しているレポート

Amazonはレポートの種類で列名がまったく違うため、**両方に対応**しています。

| レポート | 主な列 |
|---|---|
| 注文レポート | `purchase-date` / `sku` / `asin` / `product-name` / `quantity-purchased` / `item-price` / `order-status` |
| ビジネスレポート | `日付` / `(子)ASIN` / `SKU` / `商品名` / `注文された商品点数` / `注文商品売上額` |

タブ区切り・カンマ区切り、英語・日本語見出し、Shift_JIS・UTF-8 いずれも自動判定します。

### ★Amazonの商品名はあてになりません（SKUで判定します）

実際の7月のレポートを読んだところ、**商品名が途中で切れている行**がありました。

```
[リベティ] ヒルナンデス出演 スーツケース 日本企画 … S/M/Lサイズ フロントオープ
```

ここで切れていると **S・M・L の区別がつきません**。
そのため商品名ではなく **SKU で判定**しています。`config/sku-map.json` が要になります。

### 楽天の「日次 店舗データ」について

RMS の *日次_店舗データ* は、**店舗全体の合計だけ**で商品別の内訳が入っていません。
またこのファイルは **1日が4行**（すべて / PC / スマートフォン / 楽天市場アプリ）に分かれています。

- **デバイス別の行を足すと売上が約2倍になります。**「すべて」の行だけを使います
- 商品名は `(商品別内訳なし)` として正直に記録します。**推測で商品名を付けません**
- 商品別が必要なときは、RMS の **「商品別データ」** をダウンロードして同じ置き場に入れてください。
  同じ日の楽天ぶんは自動で差し替わります

読み取った日ごとの **アクセス人数・転換率・客単価** は取込ログに残ります。

### キャンセル・返品は売上に数えません

`order-status` が Cancelled / キャンセル / Returned / 返品 / Refunded の行は除外し、
**何行除外したかを表示**します。黙って減らしません。

## 6. 見るところ

### 一覧
今日 / 今週 / 今月 / すべて

### グラフ

| グラフ名 | 中身 |
|---|---|
| 今月の売上（販売先別） | Amazon と 楽天 の比率 |
| 今月の売上（商品別） | 商品ごと × 販売先の積み上げ |
| 今月の販売個数（商品別） | 個数ベース |
| 日ごとの売上（今月） | 日次推移 |
| **紐づけ要確認（今月）** | **まだ確定していない売上がいくらあるか** |

最後のグラフが大事です。ここが積み上がると、商品別の数字が信用できなくなります。
**定期的に見て、対応表に足してください。**

## 7. 項目

| 項目名 | 種類 | 備考 |
|---|---|---|
| 対象日 | 日付 | |
| 売上合計（自動） | 計算 | `SUM(s_amount)` |
| 数量合計（自動） | 計算 | `SUM(s_qty)` |
| 売上明細（販売先 × 商品） | テーブル | ↓ |
| 入力方法 / 取込ログ / 備考 | | |
| 重複防止キー | 文字列(1行) | 日付そのもの。**「値の重複を禁止する」にチェック** |

### 明細テーブル

| 項目名 | 種類 | 備考 |
|---|---|---|
| 販売先 | ドロップダウン | Amazon / 楽天 / 自社サイト / TikTok Shop / その他 |
| 商品 | ドロップダウン | 社内の商品名 |
| SKU / ASIN | 文字列(1行) | 元のレポートの値 |
| **元の商品名** | 文字列(1行) | **あとから対応表を作るために残します** |
| 数量 / 売上 / 注文数 | 数値 | |
| 平均単価 | 計算 | `IF(s_qty > 0, s_amount / s_qty, 0)` |
| **紐づけ** | ドロップダウン | **確定 / 要確認** |

## 8. まだできていないこと

**Amazonから自動でレポートを取ってくる部分（SP-API）は、まだ作っていません。**
いまはCSVを提出ボックスに置いていただく必要があります。

SP-APIを使えばCSVも不要になりますが、
Amazonの開発者登録・アプリ申請・審査が必要で、数日〜数週間かかります。
まずCSVで運用を固めてから判断するのが安全です。
