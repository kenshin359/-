# 店舗責任者 業務マニュアル（Excel）

店舗責任者ひとりが持つ3つの役割——**店舗を回す／スタッフを育てる／上司へ数字で報告する**——を、
そのまま印刷・配布して使える1冊のExcelにまとめたものです。

- 生成物：`out/店舗責任者_業務マニュアル_<担当者>さん.xlsx`（9シート）
- 中身の元：`config/store-manual.json`（**文面はすべてここ。Excelを直接書き換えないこと**）
- キントーンには一切アクセスしません。売上などの実データも含みません。

---

## 1. 作り方

```bash
cd daily-report-system
pip install openpyxl            # 初回だけ
npm run manual:store            # → out/店舗責任者_業務マニュアル_高山さん.xlsx
```

担当者・店舗・対象月を変えるとき：

```bash
python3 scripts/buildStoreManual.py --name=高山 --store=梅田店 --month=2026-09 --to=北野
```

| オプション | 内容 | 既定 |
|---|---|---|
| `--name=` | 担当者名 | JSONの `person` |
| `--store=` | 店舗名 | JSONの `store` |
| `--to=` | 報告先 | JSONの `report_to` |
| `--month=` | 対象月（`YYYY-MM`） | 実行月 |
| `--config=` | 別の設定JSONを使う | `config/store-manual.json` |
| `--out=` | 出力先 | `out/店舗責任者_業務マニュアル_<担当者>さん.xlsx` |

**パソコンに詳しくない人向け**：GitHub の「Actions」→「店舗責任者 業務マニュアル（Excel）」→
`Run workflow` で担当者名を入れて実行すると、できたExcelが画面からダウンロードできます。

## 2. 9つのシート

| シート | いつ使うか | 自動計算 |
|---|---|---|
| 使い方 | 最初に1回読む。3つの役割と守ることが書いてあります | — |
| 日次チェック | 毎日。開店前／営業中／閉店後の15項目に ✓ か ー を入れる | 実施率・当日の実施数 |
| 週次チェック | 週1回（主に月曜と金曜）。数値のふり返り・1on1・棚卸・安全点検 | 実施率 |
| 月次チェック | 月1回。目標合意・シフト・発注・月報・育成計画の更新 | 完了率 |
| 教育カリキュラム | スタッフを採ったとき／レベルを上げるとき。到達基準は全部数字 | — |
| 習得状況 | 1on1のあと。スタッフ別に1〜4で記入 | 平均・判定（Lv1〜Lv4）・項目平均 |
| KPI記録 | 毎日、閉店後。**報告に使う数字はすべてここから取る** | 成約率・客単価・合計・達成率・残りの必要日販 |
| 上司報告 | 日報・週報・月報・緊急報告を書くとき。定型文をコピーする | — |
| 判断基準 | 迷ったとき。しきい値に触れたら自分で決めずに上げる | — |

- **黄色と青字のセルが記入欄**。白地の数式セルは触らなくてよい（自動で計算されます）。
- チェック欄は `✓`（実施）と `ー`（実施せず）の2つだけ。**空欄は「まだ記入していない」扱い**で
  実施率の分母に入りません。月の途中でも率が正しく出ます。
- 実施率が **90%を下回ると赤** になります。週次のふり返りでは赤い行だけ見れば穴が分かります。
- 習得状況は低いレベルほど赤くなるので、**縦に赤い列＝店の弱点**として読みます。

## 3. 中身を直す

`config/store-manual.json` を直して `npm run manual:store` を再実行します。

| キー | 中身 |
|---|---|
| `person` / `store` / `report_to` / `channel` | 担当者・店舗・報告先・連絡手段 |
| `kpi.labels` / `kpi.targets` | KPI記録シートの列名と月間目標（売上・成約・営業日数） |
| `roles` / `rules` | 使い方シートの3役割と守ること |
| `daily` | `[時間帯, 業務, 完了の定義, 目安分]` |
| `weekly` | `[業務, 完了の定義, いつ]` |
| `monthly` | `[業務, 完了の定義, 期限]` |
| `curriculum` | `[段階, 習得項目, 到達基準, 標準日数, 確認方法]` |
| `onboarding` | 新人30日プラン `[期間, やること, 到達基準]` |
| `skills` / `skill_levels` | 習得状況シートの列と1〜4の意味 |
| `reports` / `urgent_cases` / `templates` | 上司報告のルール・緊急の定義・貼って使う定型文 |
| `escalation` | 判断基準 `[事象, しきい値, 誰が判断, いつまでに, 打ち手]` |

> **完了の定義は必ず数字で書く。**「報告した」「対応した」は完了ではありません。
> 期限と数字のない項目は、そもそもチェックリストに載せない方針です。

## 4. 運用の回し方

| いつ | やること |
|---|---|
| 毎月1日 | `npm run manual:store`（または Actions）で当月分を作り直して配布 |
| 毎日 閉店後 | KPI記録を入力 → 日次チェックに ✓ → 日報を送信（閉店後30分以内） |
| 毎週月曜 | 週次チェックの数値ふり返り → 週報（12時まで） |
| 翌月3日 | 月報（数字＋原因＋打ち手3つ） |
| 翌月5日 | 習得状況を更新し、このマニュアルを1件以上直す（月次チェックの最後の項目） |

記入済みのExcelは**月ごとに別ファイルで残す**（例：`業務マニュアル_高山さん_2026-09.xlsx`）。
翌月分は生成し直したまっさらな方を使ってください。
