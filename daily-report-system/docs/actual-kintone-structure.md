# 実際のKintone構造（調査結果）

2026-07-29 に実画面を確認して判明した、リベティさんの Kintone の実態と、
それに対するシステム側の対応方針をまとめます。

---

## 判明したアプリ

| アプリID | アプリ名 | 用途 | 本システムでの扱い |
|---:|---|---|---|
| **6** | 日報 | スタッフの日報 | **読み取り元**（`KINTONE_DAILY_REPORT_APP_ID`） |
| 7 | 売上・転換率報告 | 日次の売上報告 | 参考（既存の `src/` ツールが対応済み） |

---

## 日報アプリ（ID 6）の構造

当初の想定は「1レコード＝1人の1日」でしたが、**実際は全く違いました**。

```
レコード33
├ 各チーム名入力: LP
├ テーブル … 2026-07-01 19:37 ┬ 氏名 ミツワ ＋ 日報（自由記述の本文）
│                              ├ 氏名 三浦   ＋ 日報（自由記述の本文）
│                              └ 氏名 久保   ＋ 日報（自由記述の本文）
├ テーブル … 2026-07-02 19:37 ┬ 同じく複数人分
├ テーブル … 2026-07-03 19:37 ┬ 同じく複数人分
└ …（日付ごとに続く）
```

**特徴**

- **1レコード＝1チームの複数日分**（1人1日ではない）
- 日付は**サブテーブルの中**にある → kintone のクエリでは日付で絞り込めない
- 日報の中身は**自由記述の本文**（成果・問題・依頼などが項目分けされていない）
- 「報告日」「部署」「緊急度」「提出状況」といった**構造化された項目は存在しない**
- 同じ「日報」というラベルが、日時フィールドと本文フィールドの両方に使われている

## 売上・転換率報告アプリ（ID 7）の構造

- **1レコード＝1ヶ月**。中に「日付」＋「売り上げ報告」の欄が日数分並ぶ
- 本文は `【売り上げ】【ランキング】【詳細数値】` の決まった形式の文章
- 既存の `src/parseReport.js` が、この形式を正しくパースできることを実データで確認済み

---

## 権限について

確認時点のアカウント（LP）は、**アプリ管理権限を持つアプリが3件のみ**でした
（アプリ管理画面の一覧が「1-3/3件」表示、一方で全体のアプリ数は16）。

つまり **日報アプリ(6)の設定を変更する権限がありません**。
`/k/admin/app/edit?app=6` を開いてもアプリ管理一覧にリダイレクトされます。

## 対応方針：Kintoneを変更せず、読み取り側で吸収する

権限の制約もあり、**Kintone側は一切変更しない**方針にしました。

### 実装

`lib/extractReports.js` が、**フィールドコードに依存せず「形」から判定**して
日報を取り出します。項目名が変わっても原則そのまま動きます。

| 値の見た目 | 判定 |
|---|---|
| `2026-07-01` で始まる | その行の**日付**として記憶 |
| 短い1行の文字列（20文字以内） | 次に来る本文の**氏名**候補 |
| 長い文字列 or 改行を含む（25文字以上） | **本文**とみなし、直前の日付・氏名と組にする |

サブテーブルの中も、トップレベル直置きも、どちらも拾います。

### データの流れ

```
Kintone 日報アプリ(6)
  ↓ fetchAllDailyReportRecords()   … 全レコードを取得（$idでページング）
  ↓ extractReports()               … 日付・氏名・本文の組に展開
  ↓ filterByDate(dateISO)          … 対象日だけに絞る
  ↓ buildInputFromExtracted()      … Claude入力の形へ
  ↓ Claude                         … 自由記述を読んで経営日報を生成
  ↓ AI経営日報アプリ / LINE
```

### この方針の利点と限界

**利点**
- Kintoneの設定変更・権限取得が**一切不要**
- スタッフの入力方法を**変えなくてよい**
- アプリの項目が多少変わっても壊れにくい

**限界（正直に）**
- 「緊急度」フィールドが無いため、**緊急判定は本文の内容からClaudeが推測**します。
  確実に拾いたい場合は、本文に「至急」「緊急」などの語を入れる運用にしてください。
- 「提出状況」が無いため、**書きかけの日報も対象に含まれます**。
- 氏名と本文の対応は「短い文字列の直後が本文」という規則で判定しています。
  入力の並びが大きく変わると、対応がずれる可能性があります
  （`npm run doctor` と `node scripts/fetchDailyReports.js` で目視確認できます）。

### 確認方法

```bash
node scripts/fetchDailyReports.js --all          # どの日付に何件あるか一覧
node scripts/fetchDailyReports.js --date=2026-07-01   # その日の内容を確認
npm run doctor                                    # 取り出せているか総点検
```
