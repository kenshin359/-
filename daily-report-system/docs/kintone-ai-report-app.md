# Kintone 設定書 ②：AI経営日報アプリ

Claude が生成した経営向けサマリーを保存するアプリの設計書です。
`node kintone/createApps.js ai` で自動作成できます。

- **アプリ名**：`AI経営日報`
- **1レコード**：1日分（`target_date` は **重複禁止(unique)** → 1日1レコードで重複生成を防止）
- **フィールドコード**：`lib/format.js`（`toAiReportRecord`）と一致必須

---

## フィールド一覧

| # | 表示名 | フィールドコード | タイプ | 必須 | 選択肢 / 設定 | 用途 |
|---|--------|-----------------|--------|:---:|--------------|------|
| 1 | 対象日 | `target_date` | 日付 (DATE) | ✅ | **値の重複禁止=ON** | 何日分の報告か |
| 2 | 全体評価 | `overall_rating` | ドロップダウン | | 🟢順調 / 🟡要確認 / 🔴緊急 | 一目で状態把握 |
| 3 | 本日の結論 | `conclusion` | 文字列(複数行) | | | 1行サマリー |
| 4 | 重要成果 | `achievements` | 文字列(複数行) | | | 箇条書き |
| 5 | 問題・トラブル | `problems` | 文字列(複数行) | | | 箇条書き |
| 6 | 進捗遅延 | `delays` | 文字列(複数行) | | | 期限超過・停止 |
| 7 | 承認依頼 | `approvals` | 文字列(複数行) | | | 誰の何を |
| 8 | 社長確認事項 | `ceo_items` | 文字列(複数行) | | | 社長判断 |
| 9 | 部長確認事項 | `manager_items` | 文字列(複数行) | | | 部長判断 |
| 10 | 明日の最優先事項 | `tomorrow_priorities` | 文字列(複数行) | | | 重要順 |
| 11 | スタッフ別要約 | `staff_summaries` | 文字列(複数行) | | | 全員分1行ずつ |
| 12 | AI分析 | `ai_analysis` | 文字列(複数行) | | | 傾向・繰り返す問題 |
| 13 | LINE送信本文 | `line_body` | 文字列(複数行) | | | 実際に送った本文 |
| 14 | LINE送信日時 | `line_sent_at` | 日時 (DATETIME) | | | 送信タイムスタンプ |
| 15 | LINE送信結果 | `line_result` | ドロップダウン | | 未送信 / 送信成功 / 送信失敗 | 監視用 |
| 16 | 生成ステータス | `gen_status` | ドロップダウン | | 生成中 / 生成成功 / 生成失敗 | 監視用 |
| 17 | エラーログ | `error_log` | 文字列(複数行) | | | 失敗時の詳細 |

> **重要**
> - `target_date` の「値の重複を禁止する」を必ず ON にしてください。これが**重複送信防止の要**です。
>   同じ日で2回目の実行が来ても、追加(POST)が 400 で弾かれる／スクリプト側で既存チェックしてスキップします。

---

## APIトークンの発行

1. アプリ設定 → **APIトークン** → 生成する
2. 権限：**レコード閲覧 + レコード追加 + レコード編集**（保存と結果書き戻しに必要）
3. `.env` の `KINTONE_API_TOKEN_AI_REPORT` に設定
4. 「アプリを更新」で反映

---

## 一覧・グラフの推奨設定（任意）

- **一覧**：`対象日`（降順）→ `全体評価` → `本日の結論` を表示すると、朝イチの確認が速いです。
- **グラフ**：`全体評価` を月別に集計すると、🔴🟡 の発生傾向が見えます。
- **通知**：`生成ステータス = 生成失敗` になったら管理者に kintone 通知が飛ぶ条件通知を設定しておくと安全です。
