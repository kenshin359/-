# 1日タスク最適化AI（AI秘書）仕様書

北野マネージャ専用。毎朝タスクを貼り付けるだけで、**その日の最適な仕事順・時間割・優先順位・委任候補**が出ます。

---

## 1. 設計思想

普通のToDo整理は「重要度で並べ替える」だけで終わります。それでは足りません。
このAI秘書は、次の3つを同時に解きます。

| 解くもの | 判断の材料 |
|---|---|
| **何をやるか** | 売上/利益への影響・緊急性・他スタッフを止めていないか・今日やらない損失・経営判断としての重要度 |
| **いつやるか** | 必要な集中力（focus）と、その時間帯に残っている集中力（energy）の掛け合わせ |
| **やらないか** | 1日に使える時間の上限。超えた分は「今日やらない」と明示して切る |

大原則は **「集中力は朝がいちばん高く、15時以降は落ちる。だから頭を使う仕事に朝を使い、他人が動き出せる依頼はもっと早く出す」**。

---

## 2. 6つのカテゴリ

| 分類 | 中身 | 必要集中力 | 標準見積 | 原則の時間帯 |
|---|---|---|---|---|
| 🧠 THINK | リサーチ・分析・戦略・新規事業 | 5 | 60分 | 午前（**15時以降は禁止**） |
| 🛠 IMPROVE | LP改良・広告改善・資料/仕組み作り | 4 | 60分 | 午前 |
| 📤 DELEGATE | 依頼・指示・情報共有・通関手配 | 2 | 10分 | **朝一〜昼**（最優先で出す） |
| 👥 MEETING | 会議・相談・面談・フィードバック | 3 | 50分 | 午後（重要な意思決定は午前も可） |
| 📦 MANAGEMENT | 在庫・発注・数値確認・支払い・物流 | 2 | 20分 | 午後 |
| 📑 ADMIN | 事務・申請・返信・書類 | 1 | 15分 | 16時以降 |

依頼相手は `rules.json` の `staff`（メンバー名簿）と照合して拾います。日本語の文中から人名を機械的に切り出すと
「必要情報久保さん」のように誤るため、**推測せず名簿と `@名前` 指定だけを信用する**設計です。

判定は `config/secretary/rules.json` の辞書で行います。**長い言葉ほど強い**（「進捗確認」は「確認」より優先されるので MEETING になる）。
行末に `#THINK` と書けば自動判定より手入力が勝ちます。

## 3. 時間割（`config/secretary/profile.json`）

```
05:00        起床
05:00-06:30  朝の準備・インプット           固定
06:30-07:00  📤 朝一の依頼出し              ← 他人の着手待ちをここで全部つぶす
07:00-09:00  🧠 THINK（集中力ピーク）
09:00-11:00  🛠 IMPROVE
11:00-12:00  📤📦 依頼の残り・数字の確認
12:00-12:40  昼食                          固定
12:40-13:00  昼寝・休憩（20分）             固定
13:00-14:30  👥📦 会議・管理
14:30-14:45  休憩（15分）                   固定
14:45-16:00  👥📦 会議・管理
16:00-17:30  📑 ADMIN
17:30-18:00  明日の整理                     固定
```

`fixed: true` の枠には**絶対にタスクを入れません**（昼寝と休憩は仕事より優先されます）。
枠・時刻・受け入れカテゴリはすべてJSONで変更でき、コード修正は不要です。

### 破ってはいけないルール（コードで強制）

1. **15時以降に THINK を置かない**（`think_cutoff`）
2. **集中力4以上の仕事は16時以降に置かない**（`judgement_cutoff`）
3. 昼食・昼寝・14:30の休憩は潰さない
4. 会議が連続したら**間に10分の休憩**を自動で差し込む（`meeting_break`）
5. 60分を超える会議は「50分で区切る」と指摘する（`meeting_max_run`）
6. 5〜10分で他人が動き出す依頼は、**容量オーバーでも必ず今日出す**

## 4. 優先順位の計算

```
スコア = 3.0×売上利益インパクト + 2.5×緊急性 + 3.0×他人を止めている
       + 2.0×今日やらない損失 + 1.5×経営判断度 + 1.5×5分依頼
       + カテゴリ補正 + 0.8×持ち越し日数 − 0.6×所要時間(h)
```

- 重みはすべて `profile.json` の `weights` で調整できます。
- **カテゴリ補正**：価値を「作る」仕事（THINK/IMPROVE +1.0）を、「確かめる/こなす」仕事（ADMIN −1.0）より上に寄せます。
- **持ち越し補正**：後回しにするほどスコアが上がり、放置され続けることを防ぎます。

### 今日絶対終わらせる3つ
スコア上位から3件。ただし
**「時間が決まっている会議」**（それは予定であって成果ではない）と
**「5〜10分の依頼」**（朝一の枠で必ず片づく）は除外し、理由が重複しないよう文言を出し分けます。

### 今日やらない仕事
使える時間（固定枠を除いた合計 × 85%）を超えた分は、スコアの低い順に落とし、
**後回しにしてよい理由**と**推奨実施時間帯**（そのカテゴリを最初に受け入れる枠）を付けて返します。

---

## 5. 時間割を組む手順

1. **時刻が決まっている予定**（`13:00-14:00 部署MTG`）を先に固定し、枠から削る
2. **1周目**：そのカテゴリ専用の枠に、まるごと入るものだけ置く
3. **2周目**：受け入れ可能な他の枠に、まるごと入るものだけ置く
4. **3周目**：どうしても入らない長い仕事だけ、前半・後半に割る（最小30分）
5. 優先度がほぼ同じ（1.5点幅）なら**長い仕事を先に**置く（60分の仕事が120分枠を先取りして90分の仕事を細切れにするのを防ぐ）
6. 会議が続く箇所に休憩を挿入し、余った時間は「空き（予備・前倒し用）」として見せる

---

## 6. 出力（指定フォーマット）

`🔥 今日絶対終わらせる3つ` → `📤 朝一で人に振る仕事` → `🗓 今日のスケジュール` → `📋 タスク仕分け` → `⏭ 今日やらなくていい仕事` → `⚠️ 秘書からの指摘`

**⚠️ 秘書からの指摘** は遠慮せずに書きます。出るのは次のようなときです。

- タスクの抱えすぎ（件数・見積合計が容量超過）
- 会議の入れすぎ（4件以上または合計180分以上）
- 自分でやらなくてよい仕事（委任先を名指し＋あなたの時間の何%かを提示）
- 何日も持ち越している仕事（「やる・やめる・渡す」の3択を迫る）
- THINKがゼロ／60分未満の日（午前が事務で埋まっている）
- 分類が曖昧だったタスク（仮置きしたことを必ず伝える）
- 蓄積データからの指摘（後述）

---

## 7. 蓄積と分析（追加機能）

`state/secretary/YYYY-MM-DD.json` に1日1ファイルで保存します。
**このフォルダは `.gitignore` 済みで、GitHubには上がりません**（このリポジトリは公開設定のため）。

記録：予定タスク／完了・未完了／翌日持ち越し（回数と初出日）／見積時間と実績時間／カテゴリ／優先度スコア／実際に置いた時間帯。

`secretary review` で出るもの：

| 分析 | 出し方 |
|---|---|
| この種類の仕事は予定より時間がかかる | カテゴリ別の「実績÷見積」倍率。1.3倍以上なら翌朝の指摘に自動反映 |
| 午後はこの仕事の完了率が低い | 午前/午後/夕方の完了率。60%未満の時間帯を警告 |
| この業務は頻繁に後回しになっている | 3日以上登場して一度も完了していないタスク |
| この仕事は他人に任せた方がいい | 3回以上登場した ADMIN/MANAGEMENT/IMPROVE ＋ 委任先候補 |

翌朝の `plan` は自動でこの分析を読み、前日までの未完了を持ち越したうえでスケジュールを組みます。

## 8. 構成

```
config/secretary/profile.json   生活リズム・時間割・ルール・重み
config/secretary/rules.json     言葉→カテゴリの辞書・委任先・インパクト辞書
lib/secretary/parse.js          貼り付けたテキストを読む
lib/secretary/classify.js       分類・見積・インパクト判定
lib/secretary/prioritize.js     優先順位・今日やる/やらない・委任候補
lib/secretary/schedule.js       時間割エンジン（3パス配置・休憩挿入）
lib/secretary/format.js         指定フォーマットへの整形
lib/secretary/store.js          蓄積と分析
lib/secretary/index.js          入口（buildDailyPlan）
scripts/secretary.js            コマンド（plan / done / status / review / carry）
test/secretary.test.js          17件のテスト（ルールが壊れていないかの見張り）
```

外部送信は一切ありません。キントーンにもLINEにも触りません。手元で完結します。
