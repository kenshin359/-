# 研修資料を「大手水準」に仕上げるしくみ

パナソニックやトヨタのような大手メーカーの標準教育テキストは、**書いた人によって
質が変わらない**ことが特徴です。決まった型があり、書き方の規則があり、配る前に
チェックが入るからです。同じしくみをこのリポジトリに持ち込みました。

しくみは3つに分かれています。**AIに丸投げしない**のがポイントです。

| # | 部品 | 中身 | AI | 費用 |
|---|------|------|----|----|
| ① 基準 | `prompts/handbook-standard.md` | 章の構成・文章の規則・安全の扱い・教育設計・改訂管理 | — | 無料 |
| ② 検査 | `scripts/handbookLint.js` | 基準を機械で判定。点数と指摘一覧を出す | 使わない | 無料 |
| ③ 仕上げ | `scripts/handbookAI.js` | ②の指摘を添えて、章ごとにClaudeへ書き直させる | 使う | APIキー必要 |

---

## ① 基準（何をもって「大手水準」と呼ぶか）

`prompts/handbook-standard.md` に全文があります。要点は次のとおりです。

**章の構成は7パート固定**（順番も固定）
1. ねらい（到達目標）… 「〜できる」＋合格の合図を数値で
2. 用語の定義 … 初出の専門用語すべてに「かんたんに言うと／たとえると」
3. 手順 … 1手順1動作、動詞で終える
4. 必ず守ること … 安全・法令・お金・契約のみ。守る理由を添える
5. 目安 … 状況で変えてよいと分かる書き方
6. 確認（チェックリスト）… 第三者が◯×を付けられる粒度
7. 合格の判定 … 3項目すべて数値か観察できる事実

**文章の規則**
- 一文60字以内、1段落3文以内、能動態・言い切り
- 曖昧語の禁止：なるべく／適宜／随時／しっかり／きちんと／努める／速やかに
  → 数値か具体的な動作に置き換える（「しっかり確認」→「4箇所を指差して確認する」）
- 誇大・断定表現の禁止：絶対に／100%／必ず治る／保証します／根性論
- 安全は「危険 → 起きるケガ → 回避行動」の順。異常時は「**止める・呼ぶ・残す**」

**改訂管理**：版数・改訂日・改訂理由・作成者・承認者・次回見直し日を持つ（`meta.revision`）。

## ② 検査（配る前の合否判定）

```bash
npm run handbook:lint            # 3冊すべてを検査
npm run handbook:lint -- --strict  # 重大な指摘が1件でもあれば終了コード1（CI向け）
```

出力は「100点満点の点数（重大 −5点／注意 −1点）」と、ルール別の指摘一覧です。

| ルール | 何を見るか |
|---|---|
| `structure` | 7パートが欠けていないか |
| `solo` | 合格の判定が「理解する」「意識する」など**測れない言葉**になっていないか |
| `numbers` | 週ごとの目標が数値で書かれているか |
| `terms` | 用語に「かんたんに言うと」「たとえると」が付いているか |
| `steps` | 手順が動詞で終わっているか（名詞止めを検知） |
| `vague` | 曖昧語（目安欄は除外） |
| `banned` | 誇大・断定表現（かぎかっこの「悪い例」は対象外） |
| `long` | 一文が60字を超えていないか |
| `checks` | 1項目に2つの内容が入っていないか |
| `test` | 確認テストの解答もれ |
| `revision` | 改訂管理の欄があるか |

> **いまの状態**：トレーナー研修・新人スタッフ研修・管理職育成の3冊とも **100点（重大0・注意0）**。
> `npm test` にも「3冊は重大な指摘ゼロを保つ」というテストが入っているので、
> 文言を直して基準を割ると、テストが落ちて気づけます。

## ③ 仕上げ（AIで書き直す）

```bash
npm run handbook:ai -- --config=config/gym-handbook.json --dry-run   # 送る内容の確認（無料）
npm run handbook:ai -- --config=config/gym-handbook.json             # 書き直して out/ に保存
npm run handbook:ai -- --config=config/gym-handbook.json --write     # 採用して config を更新
npm run handbook:ai -- --config=config/newbie-handbook.json --only=3 # 第3週だけ
```

処理の流れと、**壊れないための歯止め**：

1. 先に②の検査をして、直すべき点を洗い出す
2. **章（週）ごとに**、基準＋その章の指摘＋その章のJSONだけを渡す（一度に渡す量を小さくする）
3. 返ってきたJSONの**形を確認**（キー・配列の件数・列数）。1つでも変わっていたら**採用しない**
4. もう一度②で採点し、**点数が下がったら保存しない**
5. `--write` を付けたときだけ config を更新（元ファイルは `out/*.bak` に退避）

つまり、AIが失敗しても**元より悪くなることはありません**。APIキーが無い環境では
何もせず案内だけ出して終了します（②の検査は無料で使えます）。

---

## 使う順番（おすすめ）

```bash
npm run handbook:lint                 # ① 今の点数を見る
npm run handbook:ai -- --config=... --dry-run   # ② 何を渡すか確認
npm run handbook:ai -- --config=... --write     # ③ 書き直して採用
npm run handbook:lint                 # ④ 点数が上がったか確認
npm run handbook:all                  # ⑤ PDFを作り直す
```

新しい研修資料を作るときも同じです。まず `config/*-handbook.json` と同じ形で素材を書き、
②で指摘を洗い出し、③で整え、⑤でPDFにします。
