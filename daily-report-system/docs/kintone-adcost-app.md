# Kintone「広告費管理」アプリ

**今月・昨日の総広告費、商品ごとの広告費**を Kintone の中だけで見られるようにするアプリです。

対応媒体：**Meta広告 / Amazon広告 / RPP(楽天) / Google広告 / TikTok広告 / その他**

---

## 1. 作り方

```bash
npm run create-business-apps adcost
```

作られると `KINTONE_ADCOST_APP_ID=26` のような行が表示されます。
**その行を `.env` に貼り付けてください。**

中身だけ先に確認したいときは `npm run create-business-apps adcost -- --dry-run`。

> アプリ作成には `KINTONE_USER` と `KINTONE_PASSWORD` が必要です（作成後は消してかまいません）。

---

## 2. 画面の構成

### 1レコード＝1日

入力画面はその日の「広告費シート」1枚です。

| 項目名 | 種類 | 必須 | 備考 |
|---|---|---|---|
| 日付 | 日付 | ○ | 既定は今日 |
| 総広告費（自動計算） | 計算 | | `SUM(d_cost)` … 明細の合計。**入力画面の上に出ます** |
| クリック合計（自動計算） | 計算 | | `SUM(d_clicks)` |
| 注文数合計（自動計算） | 計算 | | `SUM(d_conversions)` |
| 広告費 明細（媒体 × 商品） | テーブル | | ↓ |
| 入力方法 | ドロップダウン | | 手入力 / CSV取込 |
| 備考 | 文字列(複数行) | | |
| 重複防止キー | 文字列(1行) | | 日付そのもの。**「値の重複を禁止する」にチェック** |

### 明細テーブルの中身

| 項目名 | 種類 | 必須 | 備考 |
|---|---|---|---|
| 媒体 | ドロップダウン | ○ | Meta広告 / Amazon広告 / RPP(楽天) / Google広告 / TikTok広告 / その他 |
| 商品 | ドロップダウン | | 商品名の一覧から選ぶ。決められないものは「全体・ブランド」 |
| 販売先 | ドロップダウン | | 楽天 / Amazon / 自社サイト / TikTok Shop / 共通 |
| キャンペーン名 | 文字列(1行) | | |
| 広告費 | 数値 | ○ | 単位「円」 |
| 表示回数 / クリック数 / 注文数 | 数値 | | |
| 広告経由売上 | 数値 | | 単位「円」 |
| クリック単価 | 計算 | | `IF(d_clicks > 0, d_cost / d_clicks, 0)` |
| ROAS | 計算 | | `IF(d_cost > 0, d_revenue / d_cost, 0)` |

## 3. 見るところ

### 一覧（画面左上で切り替え）

| 一覧名 | 中身 |

| 昨日 | 昨日1日ぶん |
| 今月 | 今月ぶん（日付の新しい順） |
| 先月 | 先月ぶん |

絞り込みに `YESTERDAY()` `THIS_MONTH()` `LAST_MONTH()` を使っているので、
**月が変わっても設定を直す必要はありません。**

### グラフ

| グラフ名 | 中身 |
|---|---|
| 今月の総広告費 | 今月いくら使ったか（数字1つ） |
| 昨日の総広告費 | 昨日いくら使ったか（数字1つ） |

| 日ごとの広告費（今月） | 今月の日ごとの推移 |
| 月ごとの広告費 | 月ごとの推移 |

## 4. CSVから取り込む

```bash
npm run ads:import -- data/ads/meta_0730.csv
npm run ads:import -- data/ads/*.csv --dry-run
npm run ads:import -- data/ads/rpp.csv --media="RPP(楽天)"
```

- 媒体は見出しとファイル名から自動で判定します（分からなければ `--media=` を付ける）
- **同じ日・同じ媒体を2回取り込んでも二重になりません。**
  その媒体の明細だけを入れ替え、他の媒体はそのまま残します。

### ★期間まとめのCSVは取り込みません

「7/1〜7/30」が1行になっているファイルは、**どの日にいくら使ったか分からない**ため取り込みません。
日数で等分すると「昨日の広告費」が嘘になるからです。

**日別で書き出す手順（Meta広告）**
広告マネージャ →「レポート」→ 内訳 →「時間」→「**日別**」→ 書き出し（CSV）

Amazon広告・Google広告・TikTok広告も、レポート作成時に「日別（Daily）」を選べば同じ形になります。

どうしても1日にまとめたいときだけ `--force-date=2026-07-30` を付けてください。

## 5. レポート

```bash
npm run ads:report              # 画面に表示するだけ
npm run ads:report -- --send    # Chatwork にも送る
```

昨日の広告費と今月の累計を、**媒体別・カテゴリ別・商品別・販売先別**に出します。

送り先は `.env` の `CHATWORK_ADS_ROOM_ID`（無ければ `CHATWORK_SALES_ROOM_ID` → `CHATWORK_ROOM_ID` の順）。

## 6. キャンペーン名から商品を判定する仕組み

広告の管理画面には商品コードの欄がありません。頼れるのは**キャンペーン名だけ**です。

```
R  首振り 爆風過ぎて笑う Campaign
↑          ↑
楽天    ハンディファン(首振り)
```

対応表は **`config/ad-campaign-rules.json`** にあります。
**プログラムを触らずに、このファイルを直すだけで判定を変えられます。**

### 確実に分かるものだけ「確定」にしています

| 判定 | 意味 |
|---|---|
| 確定 | 販売先も商品も特定できた |
| 要確認 | カテゴリは分かるが、型式まで特定できない |

広告費を違う商品に付けると、**赤字の商品を黒字と誤解します。**
そのため、推測で1つにまとめることはしません。
レポートの【要確認】欄に金額の大きい順で出るので、そこを教えていただければ次回から自動で振り分けます。

### 現時点で未確定のもの

| キャンペーン名の書き方 | いまの扱い | 確認したいこと |
|---|---|---|
| `PC` | スーツケース(PC) | ポリカーボネート製と思われます。S / M / L のどれか |
| `PC多機能` | 多機能PC | 販売個数報告のどの商品に当たるか |
| `Tアル` / `Tアルミ` | Tアルミ(型式未確認) | 多機能アルミ / クラシックアルミ のどちらか |
| 先頭の `F` | 未分類 | F が何を指すか |

## 7. 「結果」列を注文数として使わない理由

Meta広告のCSVには「結果」という列がありますが、
中身は**多くの場合クリック数**です（結果インジケーターが `actions:link_click`）。

これを注文数として扱うと、**注文獲得単価（CPA）を何十倍も安く見誤ります。**
そのため、結果インジケーターが購入（`purchase`）を指すときだけ注文数として採用します。

---

## 8. 計算式に `IF` を入れている理由

広告を止めた日は広告費が 0 になります。
`d_revenue / d_cost` をそのまま書くと **0で割ることになり、エラー表示になります。**
`IF(d_cost > 0, …, 0)` にしてあるので、止めた日も画面が壊れません。

---

## 9. データの取り方

| 媒体 | 取得方法 | 自動化 |
|---|---|---|
| Meta広告 | 広告マネージャ → レポート → 内訳「日別」→ エクスポート | ◯ Marketing API で自動化しやすい |
| Amazon広告 | 広告コンソール → レポート（日別） | ◯ Advertising API あり（要申請） |
| RPP(楽天) | RMS → 広告 → RPP → 実績ダウンロード | △ APIが無いためCSV運用 |
| Google広告 | 管理画面 → レポート（日別） | ◯ Google Ads API あり |
| TikTok広告 | 広告マネージャ → レポート（日別） | ◯ Marketing API あり |

**まずは全部CSVで始めてください。** 5媒体の数字が1画面に揃うだけで、
「どこにお金を入れすぎているか」はすぐ見えます。

---

## 10. 注意：売上との突き合わせはKintoneでやらない

このアプリには**広告側の実績だけ**を入れます。
「広告費 ÷ 全体売上」のような全社の計算式は入れません。

理由は、ROASの定義（広告経由売上で見るか、全体売上で見るか）を
後から変えたくなったとき、**アプリに埋め込んだ式は直すのが大変**だからです。

全体の ROAS はダッシュボード側で計算します。定義の変更は1行で済みます。
