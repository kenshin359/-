# バックアップと安全性について

「何かあったときに対応できるように」というご要望に対する、本システムの方針と手順です。

---

## 大前提：元データ（日報アプリ）は絶対に変更しません

本システムは、スタッフ日報アプリ（ID 6）に対して **読み取りしか行いません**。

| 対象 | 操作 |
|---|---|
| 日報アプリ（元データ） | **読むだけ**（追加・変更・削除は一切なし） |
| AI経営日報アプリ | 追加・更新（AIが作った報告の保存先。新規に作るアプリ） |
| LINE | 送信のみ |

### これはテストで自動的に守られています

`test/readonly.test.js` が、**日報アプリへ書き込むコードが混入していないか**を
毎回チェックします。うっかり書き込み処理が追加されると、テストが失敗します。

n8nのワークフローJSONについても、書き込みノードが無いことを同じテストで検査しています。

```bash
npm test    # 24件すべてpassすれば、書き込み処理は存在しません
```

> このテストは「検知ロジックが本当に働くか」自体も検証しています
> （わざと違反コードを与えて、ちゃんと失敗することを確認）。

## バックアップの取り方

念のため、元データを丸ごとパソコンに保存できます。

```bash
npm run backup                # 日報アプリをバックアップ
npm run backup -- --app=7     # 売上・転換率報告アプリをバックアップ
npm run backup -- --all       # .env に設定した全アプリ
```

- 保存先：`backups/app6-2026-07-29_1530.json` のような日時つきファイル
- 中身：**Kintoneの生レコードそのまま** ＋ フィールド定義（取得できた場合）
- Kintoneは**一切変更しません**（読み取りのみ・アプリ管理権限も不要）
- `backups/` は `.gitignore` 済みなので、**GitHubには上がりません**

### いつ取るか（おすすめ）

- **最初に1回**（今の状態を残しておく）
- 運用を始める前にもう1回
- その後は、月1回程度でも十分です

## Kintone上にコピーアプリを作りたい場合

「本物とは別のアプリで練習したい」場合は、Kintoneの標準機能が使えます。

1. 対象アプリを開く → 右上 **⚙️** → **アプリ管理**
2. アプリ設定の画面で「**このアプリをコピーする**」

ただし、この操作には **そのアプリの管理権限** が必要です。
確認時点のLPアカウントには日報アプリの管理権限が無いため、
**管理者の方に依頼するか、上記の `npm run backup` で代替**してください。

> 本システムは元データを変更しないため、**コピーアプリは必須ではありません**。
> 「安心のため」という位置づけで考えていただいて大丈夫です。

## 万が一に備えて

| 心配ごと | 実際のところ | 対処 |
|---|---|---|
| 日報が消える | 書き込まないので起きません | `npm run backup` で保険 |
| 日報が書き換わる | 同上 | 同上 |
| 間違ってLINEに送る | `APP_ENV=test` の間は送信されません | 本番前に必ずプレビュー確認 |
| 同じ日に2回送る | 対象日が重複したら保存・送信をスキップします | — |
| AI経営日報が変になる | 元データには影響しません | そのレコードを削除すればOK |

## 復元について

バックアップJSONには生レコードがそのまま入っているため、
必要になった場合は、そこから復元用のデータを作れます。

現時点では**自動復元スクリプトは用意していません**。
理由は、復元＝書き込みであり、誤操作のリスクの方が大きいためです。
実際に復元が必要になった場合は、バックアップファイルをお手元に用意したうえでご相談ください。
