# 売上レポート 設定手順（Amazon / 楽天 / 自社サイト / Meta広告 / RPP広告）

5つの管理画面からダウンロードしたCSVを、**1通の売上速報**にまとめて
Chatwork（またはLINE）へ送ります。

**追加費用は基本ゼロです。** 集計はすべてプログラムが行い、Claude APIを呼びません。

---

総売上　¥106,100（前日比 +47.4%） 🔺
注文数　6件　客単価 ¥17,683

【媒体別】
Amazon　¥55,400（前日比 +24.8%） 🔺
楽天　¥36,500（前日比 +164.5%） 🔺
自社サイト　¥14,200（前日比 +2.9%）

【広告】
Meta広告　¥21,900（前日比 +19.0%） 🔺
RPP広告　¥14,200（前日比 +44.9%） 🔺
広告費計　¥36,100
ROAS　2.94　（広告費率 34.0%）

【売れ筋 TOP3】

・ドライヤー ブラック　¥27,600　2点

前日比が **−10%を下回ると ⚠️**、**+10%を超えると 🔺** が付きます。
ROASが **2.0を下回ると ⚠️** が付きます。

## 2. やること（毎日5分）

各管理画面からCSVをダウンロードして、**フォルダに入れるだけ**です。

| 媒体 | 落とす場所 |
|---|---|
| Amazon | セラーセントラル → レポート → ビジネスレポート |
| 楽天 | RMS → 受注管理 → 受注一覧のCSVダウンロード |
| 自社サイト | 管理画面の注文エクスポート |
| Meta広告 | 広告マネージャ → レポート → エクスポート |
| RPP広告 | RMS → 広告 → RPP → 実績ダウンロード |

### ⚠️ ファイル名にルールがあります

**ファイル名に媒体名が入っていること**が唯一の条件です。
どの媒体のファイルかを、名前で判断しているためです。

| ○ よい例 | × だめな例 |
|---|---|
| `amazon_2026-07.csv` | `report(1).csv` |
| `楽天_受注.csv` | `download.csv` |
| `meta_ads.csv` | `データ.csv` |
| `rpp実績.tsv` | `2026-07-29.csv` |

判別できないファイルは**無視されず**、レポートの末尾に
「【要確認】○○.csv: 媒体を判別できませんでした」と表示されます。
黙って売上から抜け落ちることはありません。

## 3. 動かしてみる（サンプルで確認）

実データを用意する前に、ダミーデータで動作を確認できます。

```bash
mkdir -p data/sales
cp samples/sales/* data/sales/
npm run sales -- --date=2026-07-29 --dry-run
```

`--dry-run` を付けると**送信せず画面に表示するだけ**なので、安全に試せます。

確認できたら、`data/sales/` の中身を消して実データを入れてください。

## 5. 文字化けについて

**対応済みです。何もしなくて構いません。**

日本の管理画面のCSVは Shift_JIS のことが多く、そのまま開くと文字化けしますが、
このプログラムは文字コードを自動判別します（UTF-8 / Shift_JIS / BOM付き / UTF-16）。

同様に、以下も自動で処理します。

- 商品名に含まれるカンマ（`"ドライヤー ホワイト, 大風量"`）
- 金額の書き方のゆれ（`1,234` / `¥1,234` / `1,234円` / `(1,234)` は −1,234）
- 日付の書き方のゆれ（`2026/07/29` / `2026年7月29日` / `20260729` / `07/29/2026`）
- タブ区切り（.tsv）
- 1注文が複数行に分かれるCSV（注文番号で1件として数えます）
- 末尾の「合計」行（日付が無い行は自動で除外し、除外件数を報告します）

## 6. 列名が合わなかったとき

「売上金額の列が見つかりません」と出た場合、その媒体の列名が
`config/sales-mapping.json` の候補に無いということです。

エラーメッセージに**実際の見出し**が表示されるので、それを候補に足してください。

```jsonc
{
  "id": "rakuten",
  "columns": {
    "amount": ["小計", "商品計", "合計金額", "ここに実際の列名を追加"]
  }
}
```

完全一致だけでなく**部分一致でも拾う**ので、
`消化金額` と書いておけば `消化金額(JPY)` にも当たります。

## 7. AIコメントを付けたい場合（任意・有料）

既定では**AIを使いません**（費用ゼロ）。
「気づきを一言ほしい」場合だけ、`.env` に次を書きます。

```
SALES_AI_COMMENT=true
```

すると末尾に1行入ります。

```
💡 広告費が前日比+28%に対し売上は+9%に留まっており、ROASの悪化にご注意ください。
```

**費用は1回あたり数円**（月あたり数十円程度）です。

### なぜ計算をAIにさせないのか

金額の集計は**すべてプログラム側**で行い、AIには**完成した数字だけ**を渡しています。

- AIに大量の足し算をさせると、金額がずれることがあるため
- 渡すデータが小さくなり、費用がほぼかからないため

AIの役割は「計算」ではなく「解釈」に限定しています。

## 8. 自動化する（n8n）

毎日決まった時刻に自動送信したい場合は、
`n8n/workflow-6-sales-report.json` を n8n に読み込ませてください。

ただし **CSVを置く作業だけは手動**になります。
Amazon SP-API・楽天RMS APIは申請と審査が必要なため、
まずは「CSVを置くだけ」で運用を始めることをおすすめします。
