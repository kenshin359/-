# Kintone「在庫管理」アプリ

**Amazon在庫** と **CS在庫（倉庫＋事務所）** を分けて記録するアプリです。
元になった在庫ファイルも一緒に添付できます。

---

## 1. 作り方

```bash
npm run create-business-apps inventory
```

作られると `KINTONE_INVENTORY_APP_ID=28` のような行が出ます。**`.env` に貼ってください。**

---

## 2. なぜ Amazon と CS を分けるのか

**これがこのアプリで一番大事な考え方です。**

Amazon(FBA)の在庫は Amazon の倉庫にあり、**楽天・自社サイトの注文には使えません。**
逆に CS の在庫は Amazon の注文には使えません。

合算して「在庫 110個」とだけ見ていると、次の2つを見逃します。

| 状態 | 何が起きているか |
|---|---|
| Amazon 0個 ／ CS 110個 | Amazonでは売り切れ表示。**FBAへ送れば売れる**のに機会損失中 |
| Amazon 28個 ／ CS 0個 | **楽天・自社の注文が出せない**。Amazonだけ売れている状態 |

どちらも「合計在庫」では絶対に気づけません。
そのため、**入力欄も、合計欄も、グラフも、すべて倉庫別に分けています。**

## 3. 画面の構成

### 1レコード＝1日

| 項目名 | 種類 | 必須 | 備考 |
|---|---|---|---|
| 基準日 | 日付 | ○ | 既定は今日 |
| 入力者 | ユーザー選択 | | 既定はログイン中の本人 |
| **在庫ファイル｜Amazon（FBA）** | 添付ファイル | | 元ファイルの置き場 |
| **在庫ファイル｜CS（倉庫＋事務所）** | 添付ファイル | | 元ファイルの置き場 |
| Amazon在庫 合計（自動） | 計算 | | `SUM(i_amazon)` |
| CS在庫 合計（自動） | 計算 | | `SUM(i_cs)` |
| 総在庫数（自動） | 計算 | | `SUM(i_total)` |
| 在庫明細（商品 × 倉庫） | テーブル | | ↓ |
| 入力方法 / 取込ログ / 備考 | | | |
| 重複防止キー | 文字列(1行) | | 基準日そのもの。**「値の重複を禁止する」にチェック** |

### 在庫明細テーブル

| 項目名 | 種類 | 備考 |
|---|---|---|
| 商品 | ドロップダウン | 売上・広告と同じ商品名の一覧から選ぶ |
| SKU/商品管理番号 | 文字列(1行) | |
| **Amazon在庫** | 数値 | FBA倉庫 |
| **CS在庫(倉庫＋事務所)** | 数値 | 事務所ぶんも含めた数 |
| 合計 | 計算 | `i_amazon + i_cs` |
| 入荷予定数 / 入荷予定日 | 数値 / 日付 | 欠品の見通しを立てるため |
| 状態 | ドロップダウン | 在庫あり / 残りわずか / 欠品 / 販売停止 |
| 備考（事務所分の内訳など） | 文字列(1行) | 事務所に何個あるかを残したいとき |

## 4. 見るところ

### 一覧

| 一覧名 | 中身 |
|---|---|
| 今日 / 今週 / 今月 / すべて | 倉庫別の合計と添付ファイルが並びます |

### グラフ

| グラフ名 | 中身 |
|---|---|
| 今日の在庫（倉庫別） | Amazon と CS の合計（数字） |
| 今日の在庫（商品別） | 商品ごとに Amazon/CS を積み上げ |
| 商品別の状態（今日） | 在庫あり・残りわずか・欠品の割合 |
| 在庫の推移（今月） | 総在庫の日ごとの動き |
| 商品別の在庫推移（今月） | どの商品が減っているか |

## 5. 在庫チェック

```bash
npm run stock:check                  # 今日の在庫を確認
npm run stock:check -- --send        # Chatwork にも送る
npm run stock:check -- --low=20      # 「残りわずか」の基準（既定10個）
npm run stock:check -- --date=2026-07-31
```

出力の例:

```
📦 在庫レポート（2026-07-31）

総在庫　145個
　Amazon(FBA) 31個 ／ CS(倉庫＋事務所) 114個
　登録商品　4件

【欠品】1件 ⚠️
　・クラシックアルミ

【残りわずか（10個以下）】1件
　・ミニハンディファン　7個（Amazon 3 / CS 4）

【Amazon倉庫が空です】FBAへ送れば売れる状態です
　・スーツケースS　CSに 110個あり

【CS在庫が空です】楽天・自社の注文が出せません
　・ハンディファン(スケルトン)　Amazonに 28個あり

【前回より大きく減った商品】（前回 2026-07-30）
　・クラシックアルミ　9 → 0個（-100%）
　・ハンディファン(スケルトン)　90 → 28個（-69%）
```

欠品や CS切れがあるときは**終了コード1**を返します。
自動実行のときに「今日は問題があった」と気づけるようにするためです。

## 6. 在庫ファイルの自動取り込みについて

**いまは添付するだけで、明細への自動入力はしていません。**

Amazon(FBA)の在庫レポートも、CS側の在庫表も、**実物をまだ見ていない**ためです。
列名を推測で決めると、在庫数を間違えて読み、欠品の判断を誤ります。

**実物のファイルを1つずつご提供いただければ、自動入力に対応します。**
それまでは、添付＋明細の手入力でお使いください（合計は自動計算されます）。

## 7. 前のバージョンからの変更

以前の設計は「1レコード＝1日×1商品」でしたが、
**1レコード＝1日＋明細テーブル**に変えました。

理由は、社長のご要望である「在庫ファイルの添付」を入れるためです。
1商品1レコードのままだと、同じファイルを商品の数だけ添付することになります。
なお、以前の設計は Kintone にまだ作っていなかったため、移行作業はありません。
