# Kintone「在庫数」アプリ 設計書

欠品による機会損失を止めるためのアプリです。
これができると、ダッシュボードの「在庫切れの疑い」が**推定から実数**に変わります。

---

## 作り方（2通り）

### A. 自動で作る（おすすめ・30秒）

```bash
npm run create-business-apps -- inventory
```

`.env` に `KINTONE_USER` と `KINTONE_PASSWORD` が要ります（作成後は消してOK）。
作らずに中身だけ見たいときは `-- --dry-run` を付けてください。

### B. 手で作る

Kintone →「アプリを作る」→「はじめから作成」→ 下の表のとおりに項目を追加。

---

## 項目

| 項目名 | 種類 | 必須 | 備考 |
|---|---|---|---|
| 基準日 | 日付 | ○ | いつ時点の在庫か |
| 商品名 | 文字列(1行) | ○ | ダッシュボードの商品名と揃える |
| SKU/商品管理番号 | 文字列(1行) | | |
| カテゴリ | ドロップダウン | | スーツケース/ファン/美容家電/トラベル用品/その他家電/その他 |
| **CS倉庫 在庫数** | 数値 | | 単位「個」 |
| **Amazon倉庫 在庫数** | 数値 | | 単位「個」 |
| 合計在庫数 | 計算 | | `stock_cs + stock_amazon` |
| 入荷予定数 | 数値 | | |
| 入荷予定日 | 日付 | | |
| 在庫状態 | ドロップダウン | | 在庫あり/残りわずか/欠品/販売停止 |
| 備考 | 文字列(複数行) | | |
| 重複防止キー | 文字列(1行) | | **「値の重複を禁止する」にチェック** |

## なぜ倉庫を分けるのか（重要）

**Amazon倉庫（FBA）の在庫は、楽天・自社サイトの出荷には使えません。**

合算で持つと「在庫は100個あるのに楽天で欠品」という状況を見逃します。
実際、御社の販売はチャネルをまたいでいるので、ここは必ず分けてください。

---

## なぜ「1日1商品1レコード」なのか

商品ごとに1レコードで上書きしていく方式だと、
**「いつ在庫が尽きたか」が後から分からなくなります。**

日ごとに記録すれば、
「7/15から在庫ゼロ → 7/15以降の売上減は欠品が原因」と説明できます。

---

## 重複防止キーについて

`2026-07-29__スーツケースS` のような文字列を入れる欄です。
「値の重複を禁止する」にチェックを入れておくと、
**同じ日の同じ商品を二重登録できなくなります。**

取り込みを2回流してしまっても在庫が二重に増えないので、必ず設定してください。

---

## 入力の運用

毎日全商品を手入力するのは現実的ではありません。次のどれかをおすすめします。

1. **CSV読み込み**（すぐできる）
   倉庫システムやAmazonセラーセントラルから在庫CSVを落とし、Kintoneの読み込み機能で取り込む
2. **主要商品だけ手入力**（週2回）
   ハンディファン・スーツケースなど、売れ筋10商品だけでも効果は大きい
3. **API連携**（後で）
   Amazon SP-API の在庫レポートから自動取得（要・開発者登録）

**まずは 2 から始めてください。** 売れ筋10商品の欠品を防ぐだけで、
ダッシュボードの「在庫切れの疑い」はほぼ実用になります。

---

## できたら

`.env` に出力された `KINTONE_INVENTORY_APP_ID=xx` を貼り、

```bash
npm run dashboard
```

でダッシュボードに在庫が反映されます。
