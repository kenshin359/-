# 韓国SNS（明洞）運用ルールと報告体制

韓国チームの「誰が・いつ・何をしているか」を見える状態にするための決めごとです。
撮影して終わり、投稿して終わりにせず **撮影 → 編集 → 投稿 → 広告 → 流入 → 予約** まで
1本の線でつないで数字を残します。

- 記録する場所: kintone アプリ **「韓国SNS運用管理（明洞）」**（1案件＝1レコード）
- 報告のリズム: **月末まとめ＋都度報告**（都度＝①事前 ②撮影後 ③投稿後 ④成果）
- 週1回、システムが未報告・遅れを自動で洗い出します（`npm run korea:sns`）

---

## 1. 4つの報告タイミング

| # | いつ | 何を報告するか | kintoneの入力欄 |
|---|---|---|---|
| ① 事前報告 | **撮影日の2日前まで** | 撮影日時・場所・内容・出演者・本数・投稿予定媒体・投稿予定日・広告利用の有無 | 「事前共有した日」〜「広告利用の予定」 |
| ② 撮影後報告 | **撮影当日中（遅くとも翌日）** | 何を撮ったか・撮影本数・編集予定本数・編集完了予定日・投稿予定日 | 「撮影本数（実績）」〜「撮影後メモ」 |
| ③ 投稿後報告 | **投稿したその日** | 投稿日・投稿URL・媒体・投稿形態・投稿の種類・広告利用の有無 | 投稿明細（1投稿＝1行） |
| ④ 成果報告 | **投稿から7日以内／以降は毎週更新** | 流入数・予約件数・来店件数・売上・振り返り | 「SNS経由の流入数」〜「振り返り」 |

報告の本文テンプレートは **[韓国チーム向け報告フォーマット（韓国語）](./korea-sns-보고양식-ko.md)** にあります。
チャットに貼る文面と kintone の欄は同じ項目なので、**チャットに書いた内容をそのまま kintone に入れる**だけです。

### 「編集担当が何をしているか分からない」への対処

編集担当は案件レコードの **編集担当 / 編集予定本数 / 編集完了予定日 / 編集完了日** を埋めます。
これだけで「いま何本を、いつまでに作っているか」が日本側から見えます。
kintone の一覧 **「編集中（期限順）」** が、そのまま編集担当の作業リストです。

## 2. 判定ルール（週次レポートが自動で見るところ）

`config/korea-sns.json` に書いてあり、変更はこのファイルを直します。

| ルール | 既定値 | 破ったときの表示 |
|---|---|---|
| 事前共有は撮影日の何日前までか | **2日前** | 🔴 事前共有が◯日前でした／記録がありません |
| 撮影後報告の期限（撮影日から） | 1日 | 🟡 当日は督促、🔴 翌日以降も未報告 |
| 編集完了予定日の超過 | 0日（当日中） | 🔴 編集が予定より◯日遅れています（担当者名つき） |
| 投稿予定日の超過 | 1日 | 🔴 投稿予定日から◯日たっても投稿の記録がありません |
| 投稿から成果入力までの猶予 | 7日 | 🔴 流入・予約が未入力です |
| 予約1件あたりの広告費（目標） | ¥8,000以内 | 🔴 超過（クリエイティブか予約導線を見直す） |

そのほか、投稿URL未記入・媒体/形態/種類の未記入・広告を使ったのに広告費が空、は 🟡 で出ます。

## 3. 週次レポートの使い方

```bash
cd daily-report-system

npm run korea:sns                       # 今週（月〜日）
npm run korea:sns -- --month=2026-09    # 指定した月
npm run korea:sns -- --all              # 全期間
npm run korea:sns -- --send             # Chatwork にも送る
npm run korea:sns -- --json=out/korea-sns.json   # 集計をファイルに出す
```

出るもの（この順で出ます。止まっているものが先です）：

```
【韓国SNS 週次まとめ（明洞）】2026-09-07 〜 2026-09-13

■ 要対応 2件（ほか要確認 3件）
🔴 9/20 明洞店 インフルエンサー撮影: 事前共有の記録がありません（撮影日 2026-09-20）
🔴 9/12 スタッフ撮影: 編集が予定より3日遅れています（予定 2026-09-10／担当 ソンチャン）
🟡 9/05 メニュー撮影: 投稿1（2026-09-06）: 投稿URLが未記入です

■ 数字
撮影 4件 / 撮影本数 11 → 編集予定 9 → 投稿 7本
再生 182,000 / クリック 1,240 / 広告費 ¥180,000
流入 860 → 予約 31 → 来店 24 / 売上 ¥1,120,000
🟢 予約1件あたりの広告費 ¥5,806（目標 ¥8,000以内）

■ 媒体別
Instagram: 4本 / 再生 120,000 / 広告 ¥180,000
TikTok: 3本 / 再生 62,000

■ 進捗
① 事前共有済み 1件 / ③ 編集中 1件 / ④ 投稿済み 1件 / ⑥ 成果集計済み 1件
```

🔴 が1件でも残っていると終了コードが 1 になります（自動実行でも気づけます）。

## 4. はじめの設定（1回だけ）

```bash
cd daily-report-system

# ① kintone にアプリを作る（パスワード認証が必要）
node kintone/createBusinessApps.js koreasns --dry-run   # まず中身だけ確認
npm run create-business-apps koreasns                   # 本番作成

# ② 表示された行を .env に貼る
#    KINTONE_KOREA_SNS_APP_ID=123
#    KINTONE_API_TOKEN_KOREA_SNS=（アプリのAPIトークン・レコード閲覧）
#    CHATWORK_KOREA_SNS_ROOM_ID=（韓国チームと共有するルーム）

# ③ 動作確認
npm run korea:sns -- --all
```

毎週月曜の朝に `npm run korea:sns -- --send` を自動実行すると、
週次まとめがそのままチャットに流れます（`scripts/nightly.sh` と同じ要領）。

## 5. この体制で見たいこと

投稿数や再生数は途中経過です。最後に見るのは次の3つです。

1. **予約が何件増えたか**（流入 → 予約 → 来店）
2. **1予約あたりいくらかかったか**（広告費 ÷ 予約件数）
3. **どの媒体・どの形態・どの出演者が効いたか**（媒体別・目的別）

「何の目的でやったのか」を先に決める欄（この撮影の目的）を必ず埋めてください。
目的のない撮影は、あとから成果を判断できません。
