# 作業指示書: STANDARD の残り7画面を実データで動かす（2026-09-19）

依頼: 北野取締役「サイトの改良をして現状どこまで触れるかみたい」
統括: 山本 ／ 実装: エンジニアAI ×3（並列） ／ 確認: 確認AIスタッフ（tsc・vitest・eslint・build・画面の実表示）

## 目的
STANDARD の12メニュー中、プレースホルダ（「次工程で実装します」）が残る7画面（売上・利益／広告分析／新商品・仕入れ／在庫管理／目標・予実管理／AI改善提案／レポート）を、**今DBにある実データ**で動く画面にする。データが無いものは「未接続」と何が必要かを正直に表示し、成功と偽らない。

## 成功条件（数字）
- プレースホルダ 7 → 0。`grep -rl "次工程で実装します" src/app` が空。
- 各画面が `npm run build` に含まれ、ログイン後に 500 を出さない（ローカル dev.db に 9/1〜9/18 のデータあり）。
- 追加した集計はすべて `src/lib/metrics/*.ts` の純関数＋vitest 検算（各画面 3件以上）。既存 129 件は全て通る。
- 画面の数字はDBの取込値のみ（推測・ハードコード禁止）。demo=true は集計から除外。

## 共通ルール（全エージェント）
- リポジトリ: `/home/user/-/dashboard`。先に `../CLAUDE.md`、`docs/metrics.md`、`docs/business.md` §5〜6、既存の `src/app/(app)/products/page.tsx`・`src/app/(app)/ads/cpa/page.tsx`・`src/lib/product-sales-data.ts`・`src/lib/pro/kpi-kintone.ts`（computeMonthlyOverview 等）を読む。
- 構成: 集計 = `src/lib/metrics/<name>.ts`（純関数）＋ `src/lib/metrics/__tests__/<name>.test.ts`。DB取得 = `src/lib/<name>-data.ts`。画面 = サーバーコンポーネント（Tailwind、日本語、`export const dynamic = 'force-dynamic'`、`getServerSession(authOptions)` で未ログインは `/login` へ）。
- 使えるテーブル: `kpiDaily`（date, salesRakuten/salesAmazon/salesOwn, target, adGoogle/adRakuten/adAmazon/adMeta, note）、`cpaDaily`、`productSalesDaily`、`target`（month/scope/scopeCode/metric/amount）、`setting`（key/value）、`proposal`、`report`、`alert`（`listOpenAlerts` in `src/lib/pro/alerts.ts`）。Order/OrderItem/Inventory/PurchaseOrder 系は demo 以外ほぼ空。
- 触らないファイル: `prisma/schema.prisma`・`prisma/postgres/schema.prisma`・migrations（列追加が必要なら Setting テーブルに JSON で持つ）、`src/components/Sidebar.tsx`、`src/components/pro-nav.ts`、`src/lib/pro/alerts.ts`、`src/lib/pro/overview.ts`、`src/middleware.ts`、`.env*`。他エージェントの担当画面。
- 完了前に `npx tsc --noEmit -p .`、`npx vitest run`、`npx eslint <変更ファイル>` を通す。**コミット・push・デプロイはしない**（山本が行う）。
- 報告: 変更ファイル一覧／画面に出るもの／テスト件数／前提・未決事項（推測で埋めた箇所は無いこと）。

## 担当A: 売上・利益（/sales）＋ 目標・予実管理（/targets）
- `/sales`: 月切替（?month=）。①月サマリー（累計売上・チャネル別・前月同期間比・日数・客単価は個数がある productSalesDaily から）②日別表（日付／楽天／Amazon／自社／合計／前日比／日別目標／達成率）③粗利は「未取得（原価率の入力待ち）」と明記（推測しない）。前月同期間比は `kpiDaily` の前月同日数で。
- `/targets`: ①月間目標（メイン／ストレッチ）の表示と編集（editor以上、`target` テーブル metric='sales' / 'sales_stretch', scope='all'）。②**イベント日加重の日別目標**: 重みは Setting `targets.weights.<YYYY-MM>` に JSON `{ "1": {"label":"…","weight":2.0}, … }` で保持。編集UI（editor以上・日ごとの重み・ラベル）。初期値として `daily-report-system/config/chorei/events-2026-09.json` の内容を Setting に投入するサーバーアクション「イベントカレンダーから読み込む」（ファイルは `../daily-report-system/config/chorei/` を読めれば読む。Vercel上で無ければ「手入力」に案内）。③日別目標 = 月間目標 × その日の重み ÷ 月内の重み合計（通常1.0）。日別実績（kpiDaily）と並べて達成率・乖離を表示。集計は `src/lib/metrics/daily-targets.ts` に（他画面が後で使う）。
- 出典表記: docs/business.md §6（通常1.0／マラソン1.7／スーパーSALE・スマイルセール2.0／最終日1.2〜1.3、メイン1.1億）。

## 担当B: 広告分析（/ads）＋ AI改善提案（/proposals）＋ レポート（/reports）
- `/ads`: 月切替。①媒体別（Google／楽天RPP／Amazon／Meta）の月合計・構成比・日別表（kpiDaily の ad* 列）②広告費率（広告費÷売上、日別・月）と現場基準 15%/20% の判定 ③7日移動の広告費 ④ROAS・CPC等は「未取得（帰属売上・クリックの取込なし）」と明記 ⑤合算CPA管理（/ads/cpa）へのリンク。集計は `src/lib/metrics/ad-daily.ts`。
- `/proposals`: `proposal` テーブル（demo除外）の一覧（状態 open/adopted/held/rejected の切替は editor以上のサーバーアクション）＋ `?tab=alerts` で `listOpenAlerts` の一覧（PRO のアラートセンターへのリンク）。提案が0件なら「ルール提案はアラートセンターと統合中。現在の異常はアラートタブ」と案内。**LLM提案は未接続と明記**。
- `/reports`: ①PRO の `report` テーブル（日報／週報／中間報告）の一覧（PRO 報告へのリンク）②定時レポートの一覧表（朝礼台本7:55／広告費11:02／売上19:07／ダッシュボード取込11:20 — docs/business.md §5.2 から。出力先と「Chatworkで見る」注記）③日別売上CSVのダウンロード（`/api/reports/daily-sales.csv?month=` Route Handler、ログイン必須、kpiDaily から）。

## 担当C: 在庫管理（/inventory）＋ 新商品・仕入れ（/purchasing）＋ 各種マスター管理（/masters）＋ 使える範囲マップ（/guide）
- `/inventory`: `inventoryMove`／`sku`／`warehouse`（demo除外）に実データがあれば SKU×倉庫の在庫表。無ければ「未接続: Kintone 在庫報告(35) のAPIトークン待ち（紐付け A7）」と、接続後に出る項目（在庫個数・末端価格・在庫金額・FBA切れ）を明記。
- `/purchasing`: `purchaseOrder`／`poLine`／`supplier`（demo除外）の一覧。無ければ「未接続」＋ 入荷予定の登録は Kintone が正、と案内。
- `/masters`: マスター一覧（Channel／Media／Warehouse／Supplier／ProductSeries／Sku／User）の件数（demo除外と demo の内訳）と各マスター画面へのリンク（既存の `/masters/*` があれば使う。無ければ件数のみ）。
- `/guide`（新規・全員閲覧可）: 「今どこまで使えるか」の地図。STANDARD 12画面＋PRO 13画面を表にし、状態（✅稼働／🟡一部／⬜未接続）・データ源・必要な紐付け（`docs/integrations.md` の番号）を表示。状態は `src/lib/site-map.ts` に定数で持ち、山本が更新する。ヘッダーやサイドバーには触らず、`/` と `/pro` からのリンクは山本が付ける。
