# Libetee 経営AIダッシュボード 仕様書

最終更新: 2026-09-16

## 目的
経営者が画面を開いて「今いくら売れ・いくら利益が残り・目標との差と原因候補・改善余地・在庫リスク・今日やるべきこと」を判断できる状態にする。
基本導線: 全体把握 → 原因の確認 → 改善案 → タスク化 → 結果確認。

## 利用者とロール
| ロール | 権限 |
|---|---|
| admin（管理者） | 全操作＋権限・マスター・取込管理 |
| editor（業務編集者） | データ取込、目標・タスク・仕入れ・在庫の登録編集 |
| viewer（閲覧者） | 閲覧・CSV出力のみ。サーバー側でも書込API拒否 |

## 初期納品範囲（本開発）
- 認証（credentials）とロール別権限制御（画面＋サーバー両方）
- 12メニュー: ダッシュボード / 売上・利益 / 広告分析 / 商品分析 / 新商品・仕入れ / 在庫管理 / 目標・予実管理 / タスク管理 / AI改善提案 / レポート / データ連携設定 / 各種マスター管理
- 統一CSV取込（マッピング→プレビュー→検証→確定）、重複防止、取込履歴、原本保持
- 売上・利益・広告・商品・在庫の集計（指標辞書 docs/metrics.md に準拠、全画面同一の集計サービス）
- 目標・予算・仕入れ案件・タスクの登録更新
- ルールベースの根拠付き改善提案（閾値設定可能）→タスク化
- CSV出力・印刷用レポート
- デモ組織データ（実データと分離、demoフラグで集計から排他）
- テスト（検算・E2E主要導線）、README、操作説明、運用手順

## 追加開発範囲（初期納品に含まない）
- 楽天/Amazon/Meta/Google の本番API自動連携（認証情報・権限・費用の確認後）
- LLMによる自然言語説明（ルールベース提案は初期版に含む）
- 外部通知、承認付きの広告変更・発注実行
- 未接続のものは画面に「未接続」「設定が必要」を表示する（成功と偽らない）

## 対象外
ジム予約・人事・採用・給与計算。多企業SaaS機能（初期版は単一企業）。

## 受入条件
依頼文【10】の16項目をそのまま受入テストとする。結果は docs/progress.md に合否と根拠を記録。

## 技術選定（2026-09-16 確認）
- Next.js 15.1（App Router, TS）+ Tailwind CSS（create-next-app@15.1.6 同梱）
- DB: **SQLite + Prisma**。理由: 本開発環境にPostgreSQLサーバーが無いため。金額は整数（円）、率はアプリ層で計算しDBに保存しないため方言依存が小さい。本番はPrismaのproviderをpostgresqlへ切替＋マイグレーション再生成で移行（手順はREADME）。
- 認証: next-auth 4.24（credentials + JWTセッション）。
- グラフ: Recharts。UI: Tailwindベースの自作カード（外部UIキット不採用。理由: 依存削減と画像レイアウトの忠実再現）。
- 検証: Zod。テスト: Vitest（計算）+ Playwright（E2E・環境のChromium使用）。

## 画面（画像基準）
- サイドバー: 濃紺 #172554系 220px、12メニュー＋ショートカット（今日のToDo/未完了タスク/アラート一覧/AIに質問する※未接続表示）
- ヘッダー: タイトル・最終更新（実取込時刻）・集計期間・比較期間・チャネル・カテゴリ・データ更新・通知・ユーザー
- 上段KPI5枚: 売上 / 貢献利益 / 広告費 / ROAS / 注文数（値・前期間比・目標比/予算消化・比較対象期間）
- 中段: モール別売上 / 日別売上推移(今週vs前週) / 月間目標vs着地予測(単純ペース予測ラベル付き)
- 中中段: アクセス・CVR・客単価・注文数スパークライン ×4 / 利益構造ウォーターフォール
- 下段: 商品別TOP10 / 仕入れパイプライン(8段のうち代表4段を表示・全段は詳細で) / 未完了タスク
- 右カラム 320px: AI改善提案(優先度順・根拠数値・影響額は「予測」ラベル) / アラート
- レスポンシブ: 1440/1280優先、768/390対応（サイドバー開閉・カード縦積み・表は表内横スクロール）
