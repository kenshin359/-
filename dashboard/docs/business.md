# リベティ メイン業務 知識ベース（アプリ開発向け）

最終更新: 2026-09-18（第1版）
目的: 経営AIダッシュボード（`dashboard/`）を「リベティの実際の業務」に合わせて作るための、業務知識のまとめ。
出典はすべてこのリポジトリ内のコード・設定・ドキュメント（`daily-report-system/`、`CLAUDE.md`）。**推測は書かない。未確定のものは「要確認」と明記する。**
本書と `metrics.md` / `data-contracts.md` が食い違う場合は、指標定義は `metrics.md`、CSV/DB粒度は `data-contracts.md` が正。本書は「業務の実態」と「差分（ギャップ）」の記録が役割。

## 3. 販売チャネル・在庫の考え方

| チャネル | 取込元 | 売上の定義（取込ルール） | 備考 |
|---|---|---|---|
| 楽天（`libetee`） | RMS受注API（毎朝7:26、夜21:17速報） | 「日次_店舗データ」は1日4行（すべて/PC/スマホ/アプリ）→**「すべて」行のみ** | RPP広告はAPI無し・CSV運用 |
| Amazon | SP-API（毎朝7:19）※停止・復旧待ちの期間あり | `item-price`=行合計（税込・送料含まず）。**キャンセル注文は数えない**。Pendingは再実行で置換 | 添付が無い日は `chorei/amazon-manual-*.json` で補完 |
| 自社サイト（Shopify） | Shopify API（毎朝7:12） | 売上=単価×数量−商品割引、**送料含まず**。キャンセル・テスト注文除外。返品は差し引かない | OAuthトークン発行1回のみ |
| TikTok Shop | 未整備 | 列名は推測（要確認） | |

- 売上の日付基準は**注文日（購入日）**。ダッシュボードの `metrics.md` は**出荷日基準**（→ ギャップ G-2）。
- 売上明細は Kintone「売上明細（自動取込）」に日付×販売先で**入替書込**（二重登録なし）。手入力の「売上・転換率報告」との差額が±1万円を超えた日だけ通知。
- 在庫は **FBA在庫（Amazon用）と CS在庫（倉庫＋事務所。楽天・自社用）を分けて判断する**。「FBA切れ」（Amazon 0・CS>0）と「CS切れ」（CS 0・Amazon>0）は別のアラート。合算在庫では判断しない。
- 期間まとめCSV（例「7/1〜7/30が1行」）は取り込まない（日数等分は嘘になる）。

## 4. 広告媒体と分類

### 4.1 媒体一覧（広告費レポートの出力順）
Google広告 → Amazon広告（内訳 SP / SB / SB2動画 / SD） → Meta広告（トラベル `trav` / カタログ `cat` / ガジェティ※手動値） → RPP（楽天） → TDA※手動値 → 案件依頼費用 → TV等 → TikTok広告※手動値 → 合計。
合算広告費（CPA用）= メタ(trav+cat) + Amazon広告 + RPP + Google。TDA・TikTok・ガジェティ等の月次手動値は**未計上**。

### 4.2 ブランド×媒体の毎日必須CSV（7欄）
【リベティ】メタ広告 / RPP / Amazon広告 / TikTok広告、【O2】Google広告 / メタ広告、【ガジェティ】メタ広告。あった時だけ: 案件依頼（各ブランド）、PRタイムズ。
→ ダッシュボードの Media マスタには **ブランド軸が無く、TikTok / TDA / 案件 / PRタイムズ / TV が無い**（ギャップ G-3）。

### 4.3 キャンペーン名からの判定（`config/ad-campaign-rules.json`）
- 販売先＝キャンペーン名の先頭1文字: `R`=楽天、`A`=Amazon、`Z`=自社サイト、`F`=未分類（要確認）。
- 商品＝キーワード（首振り／スケルトン／ミニファン／クリップ／Nアル=クラシックアルミ／Tアル=多機能アルミ／PC=スーツケース(PC・S/M/L不明)／アルミ=型式未確認 など）。
- **販売先と商品の両方が確定して初めて「確定」**。要確認の広告費は金額の大きい順に別枠で出す。
- Metaの「結果」列はクリック数のことが多い。**購入（purchase）を指す時だけ注文数として採用**（CPAを何十倍も安く見誤るため）。

### 5.3 朝礼の構成（ダッシュボード「今日やるべきこと」の原型）
①全体数字60秒（昨日の媒体別売上・計画比✅⚠️・月累計・昨日の広告費）→ ②必要日販（1.1億／1.2億ライン、直近7日の実力、「毎日あと+¥X」or「貯金ペース✅」）→ ③タスクボード（期限超過・本日期限・昨日完了）→ ④各チーム90秒（数字→学び→今日）→ ⑤今日の全社優先事項をひとつ宣言。
広告運用の朝礼基準: **CV単価3,000円以下／クリック単価10円以下**。

## 6. KPIと判定基準（現場で使われている数値）

| 指標 | 定義 | 基準・閾値 | 出典 |
|---|---|---|---|
| 月間目標 | メイン / ストレッチ | 1.1億 / 1.2億（9月は8月と同額を仮置き・未確定） | `chorei/events-YYYY-MM.json` |
| 日次目標 | 月目標 × その日の重み ÷ 月内の重み合計 | 重み: 通常1.0、楽天マラソン1.7、楽天スーパーSALE・Amazonスマイルセール2.0、イベント最終日1.2〜1.3 | 同上・`newsDaily.py` |

| 合算CPA | 合算広告費 ÷ スーツケース販売個数（全チャネル） | 目標 ¥4,500🟢 / 許容 ¥6,000🟡 / 超過🔴（客単価3万×15%/20%）。7日移動CPAも併記 | `buildCpaSheet.py` |

| ROAS | 広告経由売上 ÷ 広告費 | 2.0未満で⚠️。デイリーニュースは費用3,000円以上の広告で ≥300%🏆 / <300%⚠️ | `sales-report-setup.md`・`newsDaily.py` |

### 7.2 GitHub Actions ログの A-J 復号（Excel作成で使う）
数字 0〜9 を `A〜J` に置換してログ出力する（Actionsのシークレットマスクで数値が `***` になるのを防ぐため）。`0→A … 9→J`。復号は `'ABCDEFGHIJ'.indexOf(c)`。マーカー例: `===DAILY_CH_B===`（日別×媒体売上）、`===DAILY_CH_UNITS_B===`（日別×媒体×商品個数）、`===DAILY_SC_SALES_B===`（スーツケース系日別売上・税込）、`===SKU_B===`（`媒体|SKU`→個数）、`===ADCOST_DAILY_B===`（日別×媒体広告費。コロン後に空白あり→ `:\s*([A-J]+)`）。
