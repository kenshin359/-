# 物流進捗情報スペース｜アプリ構築ガイド

スペース「**物流進捗情報**」に、発注→物流→書類→在庫を**すべてたどれる**アプリ群を作ります。
kintone推奨のとおりアプリを分け、**番号で連携**します。

```
発注管理 ──(発注番号)──▶ 物流スケジュール ──(入庫)──▶ 在庫
  │                         │
  └─ 発注書/PI              └─ パッキングリスト・B/L・アライバル・インボイス（ファイル添付）
```

## 3つのアプリ

| アプリ | 1レコード | 主な内容 | キー |
|---|---|---|---|
| **発注管理** | 1発注(PO) | 発注番号・発注日・ライン・数量・出荷計画・関連コンテナ・発注書 | `order_no` |
| **物流スケジュール** | 1コンテナ | 出荷/BL/アライバル/通関/ドレー/入庫＋**書類ファイル**(PL/BL/AN/INV)＋監査 | `container_no` |
| **在庫** | 1SKU | 在庫合計(自動計算)・日販・発注点・在庫ステータス | `product_id` |

## 構築手順（PC・パスワード認証が必要）

```bash
cd logistics-schedule
npm install
cp .env.example .env    # サブドメイン(w6pq7i12hn4b)・KINTONE_USER/PASSWORD 等を記入

# ① アプリを3つ作成（作成後、表示される各IDを .env に設定）
npm run create-order-app        # → KINTONE_ORDER_APP_ID
npm run create-app              # 物流スケジュール → KINTONE_LOGI_APP_ID
npm run create-inventory-app    # 在庫 → KINTONE_INV_APP_ID

# ② データ投入（APIトークン認証。各アプリでトークン発行し .env へ）
npm run import-orders           # 発注9件
npm run import                  # パッキングリスト→コンテナ（BL補完つき）
npm run import-planned          # LM20260808の13本を「計画」で
PLANNED_FILE=data/planned-handyfan-abc.json npm run import-planned  # ハンディファン
npm run import-inventory        # 在庫(8/2)

# ③ 在庫・入荷ニュース生成（デイリーニュースへ自動投稿も可）
npm run stock-news
POST=1 npm run stock-news       # KINTONE_NEWS_APP_ID を設定すれば自動投稿
```

## スペースへの配置

1. スペース「物流進捗情報」を開く → **アプリ**エリアの「＋」→ 作成した3アプリを追加（またはアプリ作成時にスペース内で作成）。
2. スレッドやお知らせに「在庫・入荷ニュース」を掲示（`kintone/在庫状況_ニュース.html`）。
3. 書類は各コンテナのレコードに**ファイル添付**（パッキングリスト/B/L/アライバル/インボイス）。

## 書類の見え方

- 物流スケジュールの1レコードを開けば、そのコンテナの**PL・B/L・AN・インボイスが1画面**に揃います（`docs_status`＝不足/一部/完備）。
- 発注管理から `関連コンテナ番号` で該当コンテナへ、コンテナから `発注番号` で発注へ、双方向にたどれます。

## 連携情報をいただければ代行します

上記①〜③（アプリ作成・データ投入・ニュース投稿）まで**こちらで実行**します。
